# 푸시 보호 × gitleaks — C-3 실측

> 측정 2026-08-27 · 시크릿 코퍼스 12종(공급자 형식 6 · 일반 5 · 개인키 1) + 안전한 쌍둥이 ·
> **푸시 보호는 실제로 푸시해서** 재고, **gitleaks 는 로컬에서** 잰다
>
> [`TEMPLATE-WORKFLOWS-AUDIT`](TEMPLATE-WORKFLOWS-AUDIT.ko.md) **C-3** 을 닫는다.

## 🔴 질문의 전제가 틀렸다

C-3 은 ***"gitleaks + push protection 이 겹치는데, 겹침이 값을 하나"*** 였다.
**재보니 겹치는 게 아니라 서로 다른 것을 잡는다.**

| 부류 | GitHub 푸시 보호 | gitleaks |
|---|---|---|
| 공급자 형식 — AWS 키·시크릿 · GitHub PAT · Slack bot · SendGrid · Stripe | 🔒 **차단** | ✅ **6 / 6** |
| 🔴 **개인키 PEM** (`-----BEGIN RSA PRIVATE KEY-----`) | 🔴 **통과시킨다** | ✅ **1 / 1** |
| 일반 시크릿 — 패스프레이즈 · hex API 키 · JWT · basic-auth URL | 🔴 **통과시킨다** | 🟡 **2 / 5** |
| 안전한 쌍둥이(환경변수 · 자리표시자 · 더미) | — | ✅ **오탐 0** |

> 🔴 **개인키가 통과한 것이 가장 크다.** 커밋된 개인키는 심각한 유출인데 **막는 층이 없었다.**

## 측정 방법 — 푸시 보호는 **실제로 푸시해서** 쟀다

세 부류를 각각 브랜치로 밀었다:

```
provider   🔒 차단됨 (GITHUB PUSH PROTECTION)
generic    🔴 통과했다
pem        🔴 통과했다
```

통과한 둘은 **브랜치를 즉시 삭제**했다(값은 전부 무작위 · 진짜 자격증명이 아니다).
⚠️ **통과 = 탐지 안 함이 아니다** — 푸시 보호는 secret scanning 이 *탐지*하는 것의 **부분집합만 차단**한다.

### 🔴 1차 코퍼스가 틀렸다 — 도구를 오해할 뻔했다

처음엔 `AKIAIOSFODNN7EXAMPLE` 같은 **문서 예시값**을 심었고 gitleaks 가 3/12 만 잡았다.
그건 못 잡은 게 아니라 **그 값들이 명시적으로 allowlist 되어 있어서**다(공식 문서 예시).
**무작위 값으로 다시 만들자 6/6 이 됐다.**

> C-2 에서 CodeQL 에 출발점을 안 준 것과 **같은 형태의 실수**다.
> **코퍼스가 도구의 성질을 반영하지 못하면 숫자는 맞고 결론이 틀린다.**

## 오탐 — 실제 저장소 세 곳

| 저장소 | 결과 |
|---|---|
| `coolbress/workflows` | ✅ **0건** |
| `coolbress/project-template` | ✅ **0건** |
| `coolbress/standards` | 🟡 **1건** |

그 1건이 교과서적이다:

```
규칙: generic-api-key   매치: 'OAuth2, Argon2/bcrypt '   시크릿: 'Argon2/bcrypt'
```

**산문에서 `Argon2/bcrypt` 를 API 키로 읽었다.** 코드 저장소는 깨끗하고
**산문이 많은 저장소에서만** 문제가 된다 — 그때는 **좁은** `.gitleaks.toml` allowlist 를 쓴다.

## 판정 — **둘 다 둔다. 층이 다르기 때문이다**

| | 무엇인가 | 언제 서나 |
|---|---|---|
| **푸시 보호** | 🔒 **벽** — 서버가 거부한다. 에이전트가 못 끈다(A-1 실측: 관련 설정 **403**) | **커밋이 올라가기 전** |
| **gitleaks(CI)** | 🕸 **그물** — 머지를 막고 알린다 | **이미 올라간 뒤** |

🔴 **gitleaks 는 유출을 막지 못한다.** CI 가 도는 시점에 시크릿은 **이미 GitHub 에 있다.**
그래서 *"gitleaks 가 있으니 됐다"* 는 틀리고, *"푸시 보호가 있으니 됐다"* 도 틀리다 —
**푸시 보호가 개인키를 통과시키기 때문이다.**

### 그리고 SAST 는 이 층을 대체하지 않는다

[`C-2 실측`](SAST-CODEQL-VS-SEMGREP.ko.md): **CodeQL 도 Semgrep 도 하드코딩 자격증명을 놓쳤다.**
세 층(**벽** 푸시 보호 · **그물** gitleaks · **분석** SAST)이 **서로 다른 것을 본다.**

## 남은 것

⚠️ **`ci / secrets` 를 required check 로 올릴지는 소유자 결정**이다 — 룰셋 변경은 A-1 이후 **사람만** 할 수 있다.
올리면 벽이 세지고, 산문 저장소에서는 allowlist 관리가 따라온다.
