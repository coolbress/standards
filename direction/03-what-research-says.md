# 03 — 리서치는 무엇을 말하는가

> 재도출 2026-08-26 · **rev4**(같은 날 ⚪ 4건 해소) · 프로그램 [#49](https://github.com/coolbress/standards/issues/49) **3단계**.
> 이전 판은 원문장 뒤에 재검증 결과를 덧붙여서, **읽는 사람이 무엇에 기대도 되는지 매번 판단해야 했다.**
> 이 판은 **검증된 위치를 그대로 진술한다.** 교정의 내력은 여기 없다 — 코퍼스 claim table 과
> [`audit/`](../audit/) 에 있다. 여기는 **방향에 걸리는 것만** 추린 색인이다.

## 이 문서를 읽는 법 — 강도 표시

| | 뜻 | 쓰는 법 |
|---|---|---|
| 🟢 | **1차 확인** — **외부** 원문을 직접 열었고 독립 검증자와 일치했다 | 설계 근거로 쓴다 |
| 🟡 | 여기에 **자체 census** 도 들어간다 — 표본이 크고 재현 가능해도 **제3자 검증이 없으면 🟢 이 아니다** | |
| 🟡 | **한정** — 확인됐으나 표본·설계·범위가 결론을 좁힌다 | **한정을 지우지 않고** 쓴다 |
| 🔵 | **판단** — 리서치가 아니라 이 프로젝트의 선택이다 | **근거로 인용하지 않는다.** 바꿀 수 있다 |
| ⚪ | **미검증** — 아직 1차 출처를 열지 않았다 | **하중을 싣지 않는다** |

🔵 는 *근거가 없다*는 뜻이 아니라 **종류가 다르다**는 뜻이다. 판단을 사실로 위장하는 것이
[`EVIDENCE-POLICY`](../corpus/methods/EVIDENCE-POLICY.md) 가 이름 붙인 범주 오류(*"disguising author judgment as fact"*)다.

### 하중을 받는 것 vs 의식(ceremony)

- 🟢 **하중을 받는 것은 *"브랜치 수명 단축 + 매일 통합"* 이라는 행동**이다 (`GHW-009·010`).
- 🔵 *"브랜치 다이어그램을 정교하게 그리는 것 자체는 ceremony다"* — **판단이다.** 그 행위를 측정한 연구를 찾지 못했다.
- 🟡 **무거운 리뷰는 trunk 기반 개발의 장애물이다** — DORA 가 *"An overly heavy code-review process … **requires multiple approvals**"* 를 *Common pitfalls* 로 든다. **단 범위가 좁다** — *코드리뷰 일반의 안티패턴*이 아니라 *TBD 채택의 장애물*이고, **체크리스트는 그 페이지에 없다** · `GHW-011`

## 테스트는 어디에 있어야 하나

- 🟢 **테스트는 코드와 같은 change-unit 으로 실린다** — `04 foundation-floor` 가 *"tests required on **every PR**"* 을 MUST 로, `08` 이 test 를 **우회 불가 4대 CI 검사** 중 하나로 둔다.
- 🟢 ⭐ **에이전트에게 이것이 자기평가의 대체물이다.** 외부 피드백 **없는** 자기교정은 성공 사례가 없고(`IPW-001`), ***신뢰할 만한 외부 피드백이 있으면 잘 작동한다***(`IPW-002`) — **테스트·CI·타입체커가 그 외부 진실이다. 이 프로젝트 설계의 가장 직접적인 근거다.**
- 🟡 내재적 자기교정이 성능을 **떨어뜨리기도** 한다 — 단 **추론 과제 한정**이다 (`IPW-003`).
- 🟢 **순서가 아니라 동반이 하중을 받는다** — TDD 의 *"먼저"* 는 🟡(위 10줄 #8), **동반은 MUST** 로 나눈다.

## 게이트는 어디에 있어야 하나

- 🟢 **pre-commit 훅은 게이트가 될 수 없다.** git 자체 문서: `--no-verify` 는 *"bypasses the pre-commit and commit-msg hooks"* · `git push --no-verify` 는 *"the hook is bypassed completely"* (`IPW-005`). **진짜 게이트는 CI + 브랜치 보호다.**
- 🟡 **브랜치 보호가 강하게 걸린 저장소는 12.7%** (원자료 재계산 · Scorecard ≥8점 15/118). ⚠️ **분모 n=118 을 함께 읽는다** — 429개 중 판정 가능했던 것만이고 코퍼스가 그 한계를 *"honest coverage limit"* 로 명시한다.
- 🟢 **플랜 제약**: GitHub Free 에서 룰셋은 **공개 저장소에만** 걸린다. GitHub 자신의 응답: *"Upgrade to GitHub Pro or make this repository public to enable this feature."* (`GEB-001·002`)

## 이슈·PR 은 어떻게 쓰나

- 🟡 **이슈 우선은 크기 조건부다** — *"Issue-before-PR is **size-conditional, NOT universal**"*. 판정 기준은 줄 수가 아니라 ***"non-trivial"*** 이고, 모든 non-trivial PR 에 이슈를 요구하는 소수파는 **~20–25%**(언어 코어·유지보수자 희소 프로젝트에 몰린다). ⚠️ **표본은 CONTRIBUTING 가이드 11개 + GitHub Flow 문서** — **문서에 적힌 규범**이지 저장소 계측이 아니다 (`GHW-012`).
- 🟡 **이슈 제목에 커밋 규약을 걸지 마라** — 독립 표본 2개에서 재현: 이슈 CC **1~2%** vs **PR 33~45%**. *"이슈엔 안 쓰고 PR 엔 쓴다"* 는 **대비**가 핵심이다 (`IPC-001`).
- 🟡 **PR 템플릿 규격** — 중앙값 **3절** · **빈** 체크리스트 **62%**(중앙값 5항목) · 인라인 HTML 주석 **70%** · *"type of change"* 는 **11.5%** 뿐이라 **CC 를 쓰면 뺀다** (`IPC-002`). 🔴 **모집단을 지우지 않는다** — 제3자(**1.8M 저장소**)가 재니 **PR 템플릿 채택 자체는 전체의 1.2%** 이고 채택자는 *"mostly **prevalent** projects"* 다. **위 규격은 *상위 저장소에서 템플릿을 쓰는 곳* 의 것**이다 (`IPC-004`).
- 🟡 이슈 폼: 도움말 **87%** · required 는 **본문 필드에**(textarea 57.8% vs 체크박스 3.4%) — **체크박스에는 걸지 않는다** (`IPC-003`). ✅ **제3자가 방향을 확인해 준다** — TOSEM 2024 가 대규모 프로젝트 **100개 중 99개**가 이슈 템플릿을 쓰고 **YAML 폼 선호가 증가**한다고 보고한다 (`IPC-005`).
- 🟢 ⚠️ **이슈 폼의 `required` 는 REST/CLI 경로에 걸리지 않는다** — 에이전트는 `gh issue create` 를 쓴다. **집행은 CI 가드가 정본이다** (`GEB-003·004`).

| **분량** | 턴당 **≤2문항** | 🟢 iReDev 원문 *"Limit each question turn to no more than two questions"* / 🟡 **프롬프트 설계 선택**이지 비교 측정된 값이 아니다 · `ELI-003` |

| **완결성** | GORE **안티목표** — *"뭐가 잘못될 수 있나"* 에서 역산 | ⚪ 미검증 |

⭐ **이 절에서 가장 강한 근거** — 🟢 **흔한 실수 목록을 쥐여주면 LLM 후속질문이 사람을 이긴다.**
**통제실험 2개**다: 최소 가이드에서 *"no worse than the human-authored questions"*, 실수 유형으로 가이드하면
*"**outperform** human-authored questions"* (`ELI-001`). **④ `/kickoff` 가 실수 목록을 핵심으로 삼은 판단이 여기 선다.**
그 목록에는 **독립된 분류가 둘** 있다 — RE'25 자체 종합 **14기준**(14편 → 28 → 14) · Bano 2019 **34실수·7테마**
(🟡 학생 역할극 표본) · `ELI-007`.

🟡 **도출률 기준선**: LLM 인터뷰어는 **완전 60.94% + 부분 12.76% = 73.7%** — *"73.7%"* 만 쓰면 3분의 1이 *부분*이라는 사실이 가려진다 (`ELI-002`).

## 여러 모델을 어떻게 쓰나

- 🔵 ~~*"오케스트레이터-워커가 지배적 토폴로지"*~~ — **채택률 데이터가 없다.** 결정적으로 **같은 출처가 정반대를 쓴다**: *"**No single approach to building agents has become the standard yet**"* (`MAO-003`). → ***"널리 서술되는 토폴로지"*** 까지만 쓴다.
- 🟡 **+90.2% · 토큰 4×/15× · 토큰이 분산의 80% 설명** — 수치는 원문 그대로이나 **벤더 내부 평가**이고 표본·과제·방법론이 **공개돼 있지 않다.** 저자가 우수 영역을 *"breadth-first queries"* 로 스스로 좁힌다 (`MAO-001·002`).
- 🟡 **단일 작성자 원칙** — *"Actions carry implicit decisions, and conflicting decisions carry bad results"*(2024 Principle 2) · *"writes stay single-threaded … contribute **intelligence rather than actions**"*(2025). **근거는 통제실험이 아니라 자사 운영 경험**이고 예시에 저자가 *"This may seem contrived"* 라 단서를 단다. *"single-writer"* 라는 이름은 **이 코퍼스의 것**이다 (`MAO-004`).
- 🟡 **코딩과 다중에이전트** — 원문은 단정이 아니라 **비교문**(*"fewer truly parallelizable tasks **than research**"*)이고, 실제 부적합 조건은 **공유 컨텍스트·상호 의존**이다 (`MAO-005`).
- 🟢 ⭐ **작성자 컨텍스트가 없는 리뷰어가 더 찾는다 — 통제실험.** 30 산출물·150 주입오류·**360 리뷰**. CCR **F1 28.6%** vs 같은세션 자기리뷰 24.6%(p=0.008). **SR2 대조가 결정적** — 같은 세션에서 두 번 리뷰해도 낫지 않았다(p=0.11) → **반복이 아니라 컨텍스트 분리가 원인** (`IPW-006`).
- 🟡 **그러나 안전망이 아니다** — 최선 조건에서도 **F1 28.6%** 다. *"+16%"* 는 상대 개선이다. **게이트는 여전히 CI** (`IPW-007`). ⚠️ **놓친 비율로 옮겨 적지 않는다** — `1 − F1` 은 위음성률이 아니고 원문은 recall 을 안 낸다(2026-09-01 정정).
- 🟡 **교차벤더 라우팅은 비용이 아니라 역량 최적화** — *"a **capability router** rather than a difficulty escalator"*. 출처는 벤더 경험 보고 (`IPW-009`).
- 🟢 **호스트 제약**: 서브에이전트 `model` 필드는 **Anthropic 모델만** 받는다. 외부 모델 경로는 **MCP 또는 셸아웃 둘뿐** (`CAS-001·006`).

## 일을 어떻게 라우팅하나

- 🟡 **깊이는 위험에 비례** — Meta RADAR **535K+ diff** · 승인율 60.31% · 사고율 1/50. 🔴 ***"1/50"* 을 *"50배 안전"* 으로 읽으면 안 된다** — RADAR 통과 diff 는 **저위험으로 선별된 집단**이고 저자가 *"diffs are not randomly assigned"* 라 명시한 **관찰 연구**다 (`IPW-014·015`).
- 🔵 **계획을 *파일로* 남긴다** — 리서치가 받치는 것은 *"계획을 먼저 세운다"* 까지다. 인용해 온 Plan-and-Solve·ReAct 는 **프롬프트 내 기법**이고 파일 영속화를 주장하지 않는다 (`IPW-016`). 대체 근거도 찾지 못했다 — 에이전트 메모리 문헌은 **과거 실행의 검색**이지 계획의 영속화가 아니다 (`EVH-001`).
- 🟢 **검증은 객관 신호로** — 위 *테스트* 절과 같다 (`IPW-001·002`).
- 🟢 **실패를 경계 짓는다** — 문제는 실재한다: **6,549 저장소** 정적 분석에서 정지 경계 없는 반복 경로 **68건·47 프로젝트·정밀도 91.9%**(`IAL-SCAN-2026`). ⭐ **그리고 상한은 상수가 아니다** — *"θ is read from **healthy validation episodes** and never from test data"*. 탐지가 **관측 가능한 스텝 텔레메트리만으로** 된다(2,823 에피소드·25 데이터셋 · 복구 45% vs 대조 16%, p=0.0005) (`EVH-002`).
- 🟢 **되돌릴 수 없는 행위 전에 사람** — 자율성은 **역량과 분리된 의도적 설계 결정**이고 5단계로 구분된다. **write staging** 은 6대 아키텍처 전술 중 하나이며 해당 논문이 **reversibility 를 명시적 설계 고려사항**으로 다룬다 (`IPW-018`).
- 🟡 **LLM 심판은 자기선호 편향이 있다** — 자기인식 능력과 자기선호 강도가 파인튜닝 실험에서 **선형으로 동행**했다. 저자가 *"initial evidence"* 라 했으므로 **확정적 인과로 쓰지 않는다** (`IPW-004`).

## 생성 코드도 같은 게이트

- 🟢 ⭐ **규범이 아니라 관측된 현실이다.** 에이전트 PR **33,000건 · 에이전트 5종**: *"Not-merged PRs tend to involve **larger code changes, touch more files**, and **often do not pass the project's CI/CD pipeline validation**."* → **CI 통과 여부가 머지된 것과 안 된 것을 가른다** (`AGP-001`). 부수: 문서·CI·빌드 갱신이 머지율 최고, **성능·버그수정이 최저**.
- 🟡 **그러나 사람 손이 절반 가까이 필요하다.** Claude Code PR **567건 · 157 프로젝트**: **83.8% 머지**되지만 **무수정 통합은 54.9%** 뿐이고 **45.1% 가 사람 수정**을 거친다 — 특히 **버그 수정 · 문서 · 프로젝트별 표준 준수**. → ***"작성자가 모든 줄을 소유하고 설명할 수 있어야 한다"* 를 이 수치가 받친다** (`AGP-002`).
- ⚠️ 둘 다 **프리프린트**이고 `AGP-002` 는 **에이전트 1종·OSS 표본** 한정이다.
