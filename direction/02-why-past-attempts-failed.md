## 진단 1 — 집행을 에이전트 *안쪽*에 지었다

훅은 에이전트와 **같은 편이고, 같은 uid이며, `/plugin`으로 끌 수 있다.**
그리고 **명령 문자열만 본다.**

goppi 자신이 남긴 문장들이 결론이다:
- *"자물쇠는 협조 위에 선다."*
- *"명령 문자열만 본다 — 스크립트 파일 안의 실행은 못 잡는다."*
- *"모델이 닿을 수 없는 규칙은 규칙이 아니다."* (goppi ADR-0041)

**실측** ([`corpus/census-data/harness-confirmation-trial/`](../corpus/census-data/harness-confirmation-trial/)):

| 측정 | 값 |
|---|---|
| 실제 프로덕션을 바꾼 명령에 게이트 발화 | **11건 중 0건** |
| 발화 6건 중 오탐 | **4건 = 67%** — 전부 *"실행이 아니라 텍스트 속 언급"* |
| 완료 게이트 실사용 도달률 | **0** — 인터넷 공개까지 갔는데 개입 못 함 |
| 합성 공격 차단 | **0/4 통과** = 전부 차단 |

**마지막 두 줄이 동시에 참인 것이 핵심이다** — 합성 공격은 막았는데 실사용은 못 잡았다.
자기가 만든 시험은 통과하고 현실은 통과 못 한 것이다.

### 그리고 같은 질문에 서버 측은 답했다

goppi가 3개월간 `UNVERIFIED`로 남긴 질문 — *"이 자물쇠가 최고 권한자에게도 통하는가"* — 을
2026-08-24에 **서버 측 룰셋**에 물었더니 답이 나왔다:

```
gh pr merge --squash --admin
GraphQL: Repository rule violations found
Required status check "integrity" is failing.
```

소유자 + 관리자 권한 + 강제 플래그로도 거부됐다
([`corpus/aspects/05-scm-workflow/github-enforcement-boundaries--facts-2026-08.md`](../corpus/aspects/05-scm-workflow/github-enforcement-boundaries--facts-2026-08.md) GEB-005·006).

⚠️ **과잉 일반화 금지**: n=1이고, **룰셋을 삭제한 뒤 머지하는 경로는 측정하지 않았다.**
벽은 **표류(drift)를 막지, 결심(intent)을 막지 않는다.**

## 진단 2 — 증상을 오진했다

*"맥락이 끊긴다"* 를 **에이전트의 기억 문제**로 읽고 기억 장치를 지으려 했다.
실제로 끊기는 것은 **사람 쪽**이다 — 문제 지도 **P2**(*"내가 지금 뭘 만들고 있었고, 어디까지 한 거지?"*)와
**P18**(*"우리가 왜 이렇게 정했지"*)이 그 진술이다. *"에이전트는 매번 새로 시작하면 그만"* 은 **프로젝트 판단**이다
(측정하지 않았다).

## 진단 3 — 범위가 6배 넓었다

원한 여섯 가지 중 **다섯은 이미 팔고 있었고, 기성품이 더 강했다.**

| 원한 것 | 훅으로 지었을 때 | 이미 있는 자리 |
|---|---|---|
| 증거 보존 | G1 — 인코딩 우회 | git |
| 위험 명령 승인 | G2 — 11건 침묵·오탐 67% | 권한 규칙 · Environments |
| 완료는 증거와 함께 | G4 — 9회 후 강제 해제 | **CI + 브랜치 보호** |
| 되돌리기 | **게이트 없음**(본인 인정) | git revert · 롤백 |
| 전환점 판정 | 6개 중 1개만 구현 | CI 잡 순서 · PR |
| **소유자가 이해하고 있는가** | 없음 | **아무도 안 판다** |

남는 하나가 하필 **진단 2의 실제 증상**이었는데 그것만 안 지었다.

## 진단의 진단 — 왜 같은 실수를 다섯 번 했나

*"이미 있는 것을 확인하지 않고 새로 지으려는 기울기."*

**이 기울기는 2026-08-24 정리 과정에서 일곱 번 재현됐다.** 서수를 쓰려면 세어야 하므로 전수를 적는다:

| # | 무엇을 "없다/모른다"고 했나 | 실제 | 왜 놓쳤나 |
|---|---|---|---|
| 1 | 서브에이전트 frontmatter 8필드가 코퍼스에 없다 | `hooks-commands-subagents-standard.md`에 **이미 전부** 수록 | 전략 문서 요약표만 보고 컴포넌트 문서를 안 읽음 |
| 2 | Free+비공개 룰셋 불가는 새 사실 | `visibility-provision-matrix.md`(06-26)가 **이미 규정** | 주제가 05에 있을 거라 가정하고 04를 안 봄 |
| 3 | gingoa·goppi 리서치는 다 흡수됐다 | `RESEARCH-LIFETIME.md`·문제 지도 **미승계** | 루트 파일이 `.scratch/` 복사에 안 걸림 |
| 4 | `DECISIONS.md`는 흡수 불필요 | 스스로 *"가장 대체 불가능한 표"* — **기각한 대안**이 여기에만 | 계보에 제목만 남기면 된다고 판단 |
| 5 | claudeck-v1은 계보에 없어도 된다 | claudeck README가 *"v1에 아카이브"* 라 **적고 있었다** | README를 안 읽음 |
| 6 | claudeck-v1 저장소는 없다(404) | `~/Archive/claudeck-v1.git` **190커밋 존속**. 위치는 `sources/README.md`가 **적어놨다** | 원격만 조회하고 자기 저장소 문서를 안 읽음 |
| 7 | `direction/03` 출처 재지정 완료 | 같은 문서 **아랫절에 SUPERSEDED 인용 2건 잔존** | 지적된 좌표만 고치고 종류로 훑지 않음 |

**7번이 이 표의 요점이다.** 1~6은 *자료를 안 읽은 것*이고, **7은 수리를 좌표로 하고 종류로 하지 않은 것**이다 —
2차 적대 검수의 총평이 그것을 지적했다: *"수리가 지적 지점만 고치고 지적의 **종류**를 저장소 전체에
적용하지 않는 한, 다음 검수도 같은 형태의 결함을 다른 좌표에서 찾게 된다."*

**대책은 규율이 아니라 절차다**:
1. 새로 짓기 전에 [`MAP.md`](../MAP.md)를 주제어로 훑는다 (README 절대규칙 6)
2. **지적을 받으면 그 좌표가 아니라 그 종류를 전 저장소에 grep한다** (2026-08-24 신설)
