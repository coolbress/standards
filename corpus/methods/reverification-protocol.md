# 재검증 절차

[`EVIDENCE-POLICY`](EVIDENCE-POLICY.md) 의 *Review protocol* 은 **새 리서치를 할 때** 무엇을 기록하는지를
규정한다. 이 문서는 반대쪽 — **이미 코퍼스에 있는 주장을 다시 확인할 때**의 절차다.

## 왜 필요한가

주장은 두 번 틀릴 수 있다. **출처가 틀렸거나**, **출처는 맞는데 인용이 원문을 벗어났거나.**
후자는 검증 없이는 보이지 않는다 — 각주가 달려 있으므로 근거가 있어 보인다.

첫 사례(2026-08-24, 코드리뷰 400줄)가 정확히 후자였다. 출처는 실재했고 각주도 달려 있었는데,
**원문이 하지 않은 말을 하고 있었다.**

## 절차

### 1. 인용 사슬을 끝까지 편다

`direction` → 코퍼스 → **1차 출처**까지 각 단계에서 문장을 나란히 놓는다.
중간 단계에서 이미 어긋나는 경우가 있다 — 그러면 1차 출처를 찾기 전에 발견된다.

### 2. 주장의 종류를 먼저 분류한다

[`EVIDENCE-POLICY`](EVIDENCE-POLICY.md) §*Evidence hierarchy is claim-relative* 로 분류한다.
종류가 정해져야 **무엇이 충분한 증거인지**가 정해진다. 효과·인과 주장에 벤더 페이지를 붙이는 것은
그 표가 이름 붙인 범주 오류다.

### 3. 1차 출처를 직접 읽는다

요약·2차 인용으로 대체하지 않는다. PDF 는 텍스트를 추출해 **결론 절과 한계 절을 직접** 읽는다.
저자가 스스로 밝힌 한계·암묵 가정은 대개 각주에 있고, 요약본에는 옮겨지지 않는다.

### 4. 독립 검증자에게 같은 질문을 던진다

**내 결론을 알려주지 않고** 원문만 주고 묻는다. 유도 질문을 만들지 않는다.

```bash
codex exec --skip-git-repo-check "<원문 경로>를 근거로 …. 추측하지 말고 인용으로 답해라.
원문에 없으면 '원문에 없음' 이라고 써라."
```

⚠️ **한계**: 검증자가 Claude(Anthropic) + Codex(OpenAI) 2종이다. 갈릴 때 부르는 *"제3의 모델"* 이
Codex 의 다른 모델이면 **vendor 는 여전히 2종**이다. 완전히 독립된 셋이 아니다 — 이 한계를
*"교차검증했다"* 의 강도에 반영한다.

### 5. 갈리면 제3의 모델, 그래도 갈리면 등재

| 상황 | 처분 |
|---|---|
| 두 검증자 일치 | 판정 확정 |
| 갈림 | 제3의 모델(`codex -m <MODEL>`)에 한 번 더 |
| 셋도 갈림 | **결론 내지 말고** [`matrix--facts`](../matrix--facts-2026-08.md) 에 **충돌로 등재** |
| 원문 접근 불가 | `UNVERIFIABLE` 로 표시하고 **2차 출처임을 라벨링** |

### 6. 원문과 다르면 **주장을 고친다**

> **리서치를 근거로 우리 판단을 수정한다.** 판단에 맞춰 리서치를 고르지 않는다.
> (소유자 결정 2026-08-24 — 이 저장소의 목적이 *"객관적 리서치를 근거로"* 이므로)

수정은 **전파된 곳까지** 간다. 코퍼스만 고치고 `direction` 을 두면 다음 사람이 낡은 쪽을 읽는다.
`grep` 으로 그 수치·문구가 있는 곳을 **전수로** 찾아 함께 고친다 (README 절대규칙 7).

### 7. 기록한다

재검증 대상 문서에 다음을 남긴다 — **없으면 재검증하지 않은 것과 구별되지 않는다**:

| 필드 | 뜻 |
|---|---|
| `검증일` | 언제 |
| `검증자` | 누가 (모델·버전) |
| `1차출처` | 실제로 연 URL |
| `판정` | 유지 / 수정 / 삭제 / 충돌등재 |
| `불일치` | 검증자들이 갈렸나 |

## 무엇이 기계로 확인되고 무엇이 안 되나

**확인된다**: 절차 문서의 존재 · claim ID 등재 · `direction` 이 그 ID 를 인용하는가 ·
전파된 수치가 서로 일치하는가 · 기록 필드가 채워졌는가. 전부 `grep` 과
[`validate_corpus.py`](../../tools/validate_corpus.py) 의 범위다.

**확인 안 된다**: *"그 검증이 실질적으로 제대로 이뤄졌는가."*
기계는 필드가 채워진 것까지 보고 **판단이 타당한지는 보지 못한다.**
그래서 이 한 줄은 언제나 `UNVERIFIABLE` 이고, **사람이 1차 출처 링크를 1회 여는 것**으로 대체한다.

이 비대칭은 결함이 아니라 이 절차의 경계다. 지우지 않고 적는다.
