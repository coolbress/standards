## 이 시험이 낸 결과

| 측정 | 값 |
|---|---|
| 실제 프로덕션을 바꾼 명령에 게이트 발화 | **11건 중 0건** (미탐) |
| 발화 6건 중 오탐 | **4건 = 67%** (소유자 확정, n=6) — 전부 "실행이 아니라 텍스트 속 언급" |
| 완료 게이트 실사용 도달률 | **0** — 인터넷 공개까지 갔는데 계약이 없어 개입 못 함 |
| 승인 지연 최장 | 1시간 52분 |
| 차단 회로 (합성 공격) | **0/4 통과** = 전부 차단 |

**미탐과 차단 회로가 동시에 참인 것이 이 시험의 핵심 발견이다** — 합성 공격은 막았지만 실사용은 못 잡았다.
원인은 규칙 어휘가 표본 편향이었고, 정규식이 *언급*과 *실행*을 구분하지 못했다는 것. 수리 후에도
**스크립트 파일 안의 실행은 원리적으로 못 잡는다.**

## 왜 이게 방법론으로서 가치가 있나

- **사전등록**을 시험 전에 고정했다 — 결과를 보고 기준을 옮기지 않았다
- **vanilla 대조군**을 먼저 쟀다
- **오탐 판별이 불가능한 구조**를 발견하고 계측을 고친 뒤 다시 쟀다 (측정이지 수리가 아님을 명시)
- 결과가 자기 도구에 불리했는데 **그대로 기록했다**

결론이 무엇을 함의하는지는 `legacy/LINEAGE.md` §6.
