## 0. 이 최신화가 확인한 가장 중요한 것

**🔴 영역은 리서치로 안정화되지 않는다** — 이 세션의 전제였고, **1차 문서로 증명됐다.**

호스트의 **오늘 자 공식 문서**가 `systemMessage`에 대해 여전히 이렇게 쓴다:

```
line 151  "systemMessage": "Explanation for Claude"
line 179  systemMessage included in context
line 292  systemMessage: Message shown to Claude
```
(`~/.claude/plugins/marketplaces/claude-plugins-official/plugins/plugin-dev/skills/hook-development/SKILL.md`)

**전부 틀렸다.** 세션 #3이 5개 이벤트에서 모델 도달 **0/5**를 측정했고, 세션 #4가 그 문장이
**사용자 화면에** 뜨는 것을 사람 관측으로 확인했다.

→ **문서를 더 읽어도 이 오류는 안 고쳐진다. 실측만이 고친다.**
   `🔴` 딱지의 근거가 추정이 아니라 **현행 문서에서 재확인된 사실**이 됐다.

부수로 같은 교훈 하나 더: 2차 자료(블로그)가 *"marketplace.json에 context-cost 추정치가 들어간다"*고
썼는데, **공식 문서 전문 검색 결과 `contextCost`·`context cost` 모두 0건**이었다. 채택하지 않았다.

## 1. ① 훅 동작·플러그인 규격 — 실측 결과

### 1.1 매니페스트 규격은 **바뀌었다** (census 이후 신설 필드)

공식 문서(`code.claude.com/docs/en/plugin-marketplaces`)에서 확인한 신설·버전 게이트 필드:

| 필드 | 요구 버전 | 뜻 |
|---|---|---|
| `displayName` | v2.1.143+ | UI 표시용 이름 (namespacing에는 안 씀) |
| `renames` | v2.1.193+ | 플러그인 이름 변경·삭제 시 기존 사용자 자동 이관 |
| `metadata` | v2.1.222+ | 자유 형식 필드. **그 이전 버전에서는 `validate`가 미인식 키로 신고** |
| `allowCrossMarketplaceDependenciesOn` | — | 다른 마켓플레이스 의존 허용 목록. 미등재 의존은 **설치 시 차단** |
| `strict` | — | `false`면 마켓 항목이 완전한 매니페스트 역할(plugin.json 불필요) |
| 플러그인 의존성(semver) | — | 별도 문서 `/docs/en/plugin-dependencies` |

**goppi에 대한 함의**: `renames`는 **이름을 바꿀 여지를 지금 확보**해 둔다는 뜻이다.
오픈소스로 낼 계획이면 초기에 넣어두는 게 싸다.

### 1.2 검증 명령이 있다 — **실측 완료**

```
$ claude plugin validate harness/goppi
Validating plugin manifest: …/harness/goppi/.claude-plugin/plugin.json
✔ Validation passed          (exit 0)
```

→ goppi 매니페스트는 **v2.1.226 규격에 적합**하다. (CI에 넣을 후보 1순위)

### 1.3 아직 안 한 것

훅 출력 표면은 세션 #3이 8채널 × 5이벤트로 측정했고 그 결과는 유효하다.
**`Stop` 이벤트의 사용자 렌더링만 여전히 미측정**이며, 그것이 다음 세션 ⓪이다.

## 2. ② 컴포넌트 빌드 방식 — Skills 규격 확인 + **이식성 함정**

### 2.1 Skills 규격 (현행 확인)

```
skill-name/
├── SKILL.md (필수)
│   ├── YAML 프론트매터: name(필수) · description(필수)
│   └── 마크다운 본문(필수)
└── 선택: scripts/ · references/ · assets/
```

`description`은 **3인칭**으로 쓴다(*"This skill should be used when…"*). 발동 여부가 여기서 갈린다.
→ PART IV 시공 도면 §1과 **일치**. 이 부분은 안 바뀌었다.

### 2.2 새 사실 — Agent Skills가 **오픈 표준**이 됐다 (2025-12-18)

Anthropic이 사양과 SDK를 공개했고, **Codex · Gemini CLI · GitHub Copilot · Cursor · VS Code 등
20+ 플랫폼이 채택**했다. (2차 자료 다수 일치 · 1차 사양 원문 미대조 → **부분 확인**)

⚠️ **그리고 함정이 있다** — 이게 goppi 설계에 직접 영향을 준다:

> 도구들이 표준을 **비표준 프론트매터 필드로 확장**하고, 그런 필드에 의존하는 스킬은
> **조용히 이식성을 잃는다 — 파일은 로드되는데 그 동작만 무시된다.**

**"조용한 실패"**는 이 프로젝트가 가장 경계하는 형태다(거짓 초록). goppi가 스킬을 쓸 때
호스트 전용 필드를 쓰면, 다른 호스트에서 **에러 없이 규율만 사라진다.**

→ **설계 반영 필요**: 스킬의 프론트매터는 표준 필드만 쓰고, 호스트 전용 확장은
   **쓰더라도 그것이 없을 때 무엇이 사라지는지 명시**한다.

## 3. ③ 생태계 — **census의 "빈 칸 3종"에 정정이 필요하다**

### 3.1 census가 맞는 부분

*하네스 증강 패키지* 범주 안에서 `{비엔지니어 사용자 + 아이디어→골격 + spec준수 eval}`
3중 교집합이 비어 있다는 판정 자체를 뒤집을 근거는 못 찾았다.
그리고 카테고리에 **이름이 생겼다** — `awesome-harness-engineering` 큐레이션 리스트 존재(2차).

### 3.2 ⚠️ 그러나 **"경쟁이 없다"로 읽으면 틀린다**

census는 분류에서 **"G. 제품·앱·도메인 ~28"을 명시적으로 제외**했다. 그런데 그 제외된 칸에
**비엔지니어를 정면으로 노리는 자금력 있는 경쟁자**들이 있다 (2차 자료):

| | 상태 (2026-08-08 재확인 · 복수 2차 자료 일치) |
|---|---|
| Lovable | ARR **$400M**(2026-02) → **$500M**(중반) · 밸류 **$6.6B → $13.2B** (Forbes: $12B 협상 보도, 2026-06) |
| Replit | 밸류 **$3B**(2025-09) → **$9B**(2026-03) · Series D **$400M** |
| Bolt.new | 0 → **$40M ARR**을 약 5개월에 |

**"0/27"은 "하네스 패키지 중엔 없다"는 뜻이지 "비엔지니어 시장이 비었다"는 뜻이 아니다.**
이 오독은 위험하므로 여기 못박는다.

**goppi가 이들과 갈리는 지점**(판단, 근거 아님): 저들은 **앱을 만들어 준다.**
goppi가 하려는 것은 **유지·검증·인계가 가능한 프로젝트를 남기는 것**이다.
이 차이가 실제로 사용자에게 값이 있는지는 **미검증**이며, 그것이 곧 worth 가설이다.

부수: **"supervised AI building"**(시니어가 AI로 프로덕션급 산출)이라는 인접 카테고리가 형성 중(2차).

### 3.2b 전수조사 재실행 (haiku 서브에이전트 8개, 2026-08-08) — **숫자는 못 얻었다**

사용자 요청으로 27개 저장소를 haiku 에이전트로 재조사했다. **결론부터: 채택률 숫자는 갱신 실패다.**

**왜 실패인가 — 도구가 다르다:**
원판은 에이전트 27개·617k 토큰으로 **파일트리를 깊이** 팠고, 이번은 GitHub 페이지를 WebFetch로 봤다.
에이전트들이 스스로 남긴 말들이 그 차이를 보여준다:

- *"`.githooks/`가 있는데 `hooks.json`이 아니라 엄격 기준상 없음 처리"*
- *"`src/hooks/`라 규격에 안 맞아 안 셈"* · *"`template/`(단수)라 `templates/`(복수)로 안 셈"*
- *"`plugin.json` fetch가 404 — 디렉터리 구조로 있다고 추정했으나 직접 확인 못 함"*
- *"`.github/workflows/` 경로가 404라 **보수적으로 없음 처리**"*

한 에이전트는 직접 이렇게 적었다: *"기준선이 불완전했거나, 프로젝트들이 실제로 컴포넌트를
제거·재편했거나 **둘 중 하나**."* — **그 둘을 이 방법으로는 못 가른다.**

**결정적 반례**: `Yeachan-Heo/oh-my-codex`가 **12/12 → 3/12**로 나왔는데, 같은 에이전트가
*"agents·commands·hooks·plugin 설정·evals·constitution이 **중첩된 플러그인 디렉터리
(`.agents/plugins/`, `plugins/oh-my-codex/.mcp.json`)에만** 있다"*고 적었다.
`wshobson/agents`도 같다 — *"175 skills·203 agents·109 commands가 `plugins/<name>/` 아래 중첩"*.
**즉 있는 것을 못 본 것이지 없어진 게 아니다.** 이 한 사례가 재조사 전체의 숫자를 무효화한다.

→ **`Skills 89% · CI 81%` 등의 채택률은 2026-06-21 값 그대로 두고 `잠정`을 유지한다.**
   *"카테고리가 쪼그라들고 있다"*는 결론을 내리지 않는다. **측정 차이일 가능성이 크다.**
   서로 다른 도구가 낸 숫자를 비교하지 않는다 — 이 저장소의 규율 그대로다.

**그래도 이진값(있다/없다)은 신뢰할 수 있고, 거기서 확실한 것:**

## 3.4 **판정 갱신 — 빈 칸 3종 중 둘이 닫혔거나 좁아졌다**

| 축 | 2026-06 판정 | **2026-08-08 판정** | 근거 |
|---|---|---|---|
| **아이디어 → 프로젝트 골격** | 0/27 | ❌ **점유됨** | **GitHub Spec Kit — 125,800⭐ · MIT.** 7단계(Constitution → Specify → Plan → Tasks → TasksToIssues → Implement → **Converge**). ⚠️ **단 사용자는 개발자다** — 전제조건이 `Python 3.11+`·`git`·CLI |
| **현업 프로세스를 입힌다(①)** | (census 축 아님) | ❌ **경합 심함** | `addyosmani/agent-skills` 81k⭐ · 호스트 내장 `feature-dev` |
| **spec 준수 / 시니어급 감사** | 0/27 | ⚠️ **부분 점유 — 대상이 다르다** | `microsoft/assert`(MIT, 219⭐)는 *"AI 에이전트·LLM 앱"*의 **행동**을 평가한다. goppi ③은 *"에이전트가 **만든 소프트웨어**"*를 본다 — **다른 물건** |
| **비엔지니어가 사용자(②)** | 0/27 | ✅ **여전히 열림** | Spec Kit·addyosmani·ASSERT 전부 엔지니어 대상. "Record a Skill"은 비엔지니어용이나 **스킬 제작**이지 **판단 지원**이 아니다 |

②의 보강 증거 — 27개 중 유일한 **12/12 완전체**였던 `oh-my-codex`의 README 자기 규정:
> *"순정 Codex를 원하고 추가 워크플로 층이 필요 없다면, 당신은 아마 OMX가 필요 없다."*

→ **이미 Codex를 쓰는 개발자**를 전제한다. 가장 완성도 높은 패키지조차 비엔지니어를 상정하지 않는다.

**⚠️ goppi 설계에 대한 직접 함의 — 스테이션 6종은 차별화가 아니다.**
goppi의 `S0 묻는다 → S1 계획한다 → S2 만든다 → S3 확인한다 → S4 내보낸다`는
Spec Kit의 7단계와 **거의 동형**이고, 심지어 **`Constitution`이라는 단어까지 같다.**
125,800⭐짜리 무료 도구가 이미 하고 있다. **단계 순서로는 경쟁이 안 된다.**

→ **남는 것은 ②(비엔지니어가 판단할 수 있게)와 증거 결합(조인)이다.** 나머지는 상품화됐거나 경합 중이다.

### 3.5 호스트가 이미 하는 것 — **짓기 전에 이것부터 봐라**

공식 마켓플레이스 39개 플러그인 중 goppi 스테이션과 겹치는 것(로컬 실측):

- **`feature-dev`** — *"코드베이스 탐색·아키텍처 설계·품질 리뷰 전문 에이전트를 갖춘 기능 개발 워크플로"* ← ~~S1~S3~~ → **S1~S2만**
- `code-review` · `pr-review-toolkit` · `security-guidance` · `commit-commands` · `project-artifact` · `ralph-loop`

**Anthropic 패턴 1(*"이미 아는 것을 써라"*)의 직접 적용 대상이다.**

> 🔴 **2026-08-10 정정 — 위의 "S1~S3"는 과대 서술이었다.** 소스를 직접 읽고 실측:
> ① `feature-dev/agents/*.md` 3종 전부 tools에 **`Bash`가 없다**(`BashOutput`·`KillShell`만) —
>    **리뷰어가 테스트를 물리적으로 실행할 수 없다.**
> ② `code-review/commands/code-review.md`가 명시: *"빌드 신호를 확인하지 마라. 앱을 빌드/타입체크하지
>    마라 — 따로 돌아간다"* 이고, **"테스트 커버리지 부족"을 오탐 예시로 배제**한다.
> ③ `feature-dev` Phase 7은 *"무엇을 만들었는지 요약"* — **자기보고**이며 실행 증거와의 조인이 없다.
> → 호스트가 덮는 것은 **"코드가 잘 짜였나"(품질 리뷰)이지 "약속한 것이 실제로 실행됐나"(S3)가 아니다.**
> S3는 비어 있는 게 아니라 **의도적으로 비워둔 자리**다. 배치를 옮길 때 이 구분을 지운 채 옮기면
> goppi는 자기 자리를 남에게 넘겼다고 착각한다.
>
> 🔴 **정정 2 — `hookify`는 "빈 틀"이 아니다.** `hookify/core/rule_engine.py:76`이 실제로

판별할 수단이 없다.** "판단할 수 있게 만든다"가 취향이 아니라 **안전 요구**가 된다.

## 4. 예상 밖 최대 수확 — **Anthropic 공식 하네스 설계 지침**

사용자가 *"프론티어 회사들의 아티클대로 goppi를 빌드하고 싶다"*고 한 것의 1차 자료를 찾았다.

### 4.1 하네스 설계 3패턴 (`claude.com/blog/harnessing-claudes-intelligence`)

| # | 패턴 | 처방 |
|---|---|---|
| 1 | **모델에 기대라, 하네스에 기대지 마라** | Claude가 이미 아는 **범용 도구**(bash·텍스트 편집기)를 쓴다. 전용 도구는 모델이 좋아지면 불필요해진다 |
| 2 | **하네스를 벗겨내라** | *"하네스는 Claude가 **혼자 못 하는 것에 대한 가정**을 인코딩한다."* 모델이 좋아지면 그 가정이 **죽은 무게(dead weight)**가 된다 |
| 3 | **경계를 신중히 설정하라** | UX·비용·**보안**만 하네스로 강제. 고위험 행동만 전용 도구로 승격해 게이팅·관측 |

→ **사용자 목적 2)(경량화·모델에 자유도)가 Anthropic 공식 처방과 일치한다.** 직감이 아니라 근거가 됐다.
→ 그리고 **자기제거 규율**(빼도 결과가 같으면 삭제)은 패턴 2 그 자체다.

⚠️ **goppi에 대한 직접 함의**: 패턴 3은 *"UX·비용·보안만"* 강제하라고 한다.
**G1(증거 경로 보호)은 셋 중 어디에도 해당하지 않는다** — 하네스가 자기 로그를 지키는 것이다.
컷 후보라는 판정이 외부 근거를 하나 더 얻었다.

### 4.2 장기 실행 하네스의 실제 구조 (`anthropic.com/engineering/effective-harnesses-for-long-running-agents`)

**이것이 사용자 목적 ①·③·④의 구체적 형태를 이미 보여준다:**

| 요소 | 내용 |
|---|---|
| **2단계 에이전트** | **Initializer**(1회 — 환경 scaffold) + **Coding**(이후 세션 증분 작업) |
| **유지 산출물 4종** | `claude-progress.txt`(세션 간 작업 로그) · `feature_list.json` · `init.sh`(개발서버 실행) · **git 저장소** |
| **거짓 완료 방지** | `feature_list.json`을 **전부 `failing`으로 시작**하고, *"신중히 테스트한 뒤에만 `passing`으로 표시"* |
| **end-to-end 검증** | 브라우저 자동화로 **사람 사용자처럼** 시험 |
| **세션 시작 절차** | `init.sh`를 읽고 기본 동작을 확인한 뒤 새 작업 시작 |
| **git의 역할** | 버전관리 **+ 상태 복구** — *"나쁜 변경을 되돌려 동작하던 상태로 복구"* |

**세 가지가 곧바로 맞물린다:**
- `feature_list.json` 전부 failing 시작 → **goppi 조인 규칙과 같은 계열**(증거 없이 초록 금지).
  우리가 발명한 게 아니라 **Anthropic도 같은 자리에 같은 장치를 뒀다.**
- git = **되돌리기** → 사용자 목적 ④의 공식 근거. "현업이 그러니까"가 아니라 **상태 복구 수단**이다.
- `claude-progress.txt` → 세션 경계를 넘기는 인계. goppi의 `NEXT-SESSION.md` 회전과 같은 문제의식.

### 4.3 OpenAI 「Harness engineering」 — **이번 리서치에서 설계를 가장 크게 바꿀 발견**

`openai.com/index/harness-engineering/` (그 외 `unlocking-the-codex-harness` · `unrolling-the-codex-agent-loop` ·
`developers.openai.com/codex/learn/best-practices` · `/codex/skills`)

| 처방 | 내용 |
|---|---|
| **틀은 "린터와 구조 테스트"로 기계적으로 강제한다** | 도메인 안에서 코드는 정해진 층을 따라 **앞으로만** 의존할 수 있다 (Types → Config → Repo → Service → Runtime → UI). 이 제약을 **커스텀 린터·구조 테스트로 집행**한다 |
| **지도를 줘라, 1,000쪽 매뉴얼을 주지 마라** | *"하나의 큰 `AGENTS.md`"* 방식은 **실패했다.** 컨텍스트는 희소 자원이라 거대한 지시문이 과제·코드·문서를 밀어낸다 |
| **강한 아키텍처 제약이 조기 전제조건** | *"제약이 있어야 부패와 표류 없이 속도가 난다"* |
| **반복되는 일은 스킬로 만든다** | 팀의 주 업무가 **에이전트가 일할 수 있게 만드는 것**으로 바뀐다 (design·code·review·test로 분해) |

**왜 이게 goppi에 결정적인가 — 세 가지가 동시에 풀린다:**

1. **사용자 목적 ①("틀만 강제")의 구현 방법이 나왔다.**
   OpenAI의 답은 **런타임 가로채기가 아니라 저장소 안의 린터·구조 테스트**다.

2. **그 방식은 `🟢`다.** 훅으로 강제하면 호스트 규격에 매달려 `🔴`가 되지만,
   **린터·테스트·CI로 강제하면 git 위에 서므로 `🟢`가 된다.**
   → `RESEARCH-LIFETIME.md`의 의존 목록이 **줄어든다.** 이게 "엎지 않으려면" 정확히 필요한 것이다.

3. **G1 문제도 같이 풀린다.** 명령 **문자열**을 추측하는 매처가 오탐을 냈다.
   ⚠️ **2026-08-08 정정(적대 감사 F-4)**: 이 문단의 첫 판은 그 오탐을 *"9회 + FP-2 4회"*로 적고
   **전부 G1 몫인 것처럼** 썼는데 **원 기록과 모순된다** — FP-2 ①②는 **G2 발화**이고
   (`records/2026-08-06-slice1-runtime.md:104` 및 §13), G1 확정은 ④뿐, ③은 UNVERIFIED다.
   **G2는 절단 후에도 남으므로 ①②는 사라지지 않는다.** 린터·구조 테스트로 옮겨서 얻는 이득은
   **G1 몫에 한정**된다. (자세히: `ENFORCEMENT-MAP.md` §2.4b)
   린터·구조 테스트는 **결과물을 본다** — 추측이 없고, 사용자가 직접 볼 수 있고, CI에서 돈다.

⚠️ **동시에 경고이기도 하다**: *"큰 AGENTS.md는 실패했다"* — goppi의 L0는 46줄/3,309B로 아직 지도 쪽이다.
그러나 설계 문서의 **스테이션 6종을 지시문으로 부으면 정확히 그 실패**로 간다.
스테이션은 **상시 지시문이 아니라 조건부로 펼쳐지는 Skills**여야 한다(양 사가 같은 처방).

### 4.4 두 회사가 **수렴한 것** — 이게 기준점이다

| 축 | Anthropic | OpenAI |
|---|---|---|
| 상시 지시문 | 최소로 (부트로더) | **"지도, 매뉴얼 아님"** — 큰 AGENTS.md는 실패 |
| 반복 절차 | 조건부 Skills | **"반복되는 일은 스킬로"** |
| 강제 | UX·비용·보안**만** | **린터·구조 테스트** |
| 모델이 좋아지면 | **벗겨내라** (죽은 무게) | 제약은 유지하되 지시문은 최소 |
| 상태·복구 | git + progress 파일 | 구조 테스트가 표류를 잡음 |

→ **`{작은 상시계약 + 조건부 스킬 + 기계적 구조 검사 + git}`이 두 프론티어 랩의 공통 처방이다.**
   goppi가 지금 가진 것: 작은 상시계약 ✅ · 조건부 스킬 ❌(0개) · 기계적 구조 검사 ❌ · git 활용 ❌

## 5. 새 증거 — **goppi가 노리는 문제가 실재한다는 측정값**

census에 없던 축이고, 사용자가 *"그 차이에 값이 있는지 알아봐 달라"*고 한 항목이다.
*"AI가 앱은 만들어 주는데 유지·검증 가능한 프로젝트는 안 남긴다"*가 **측정됐다** (2026 연구들 · 2차 다수 일치):

| 측정 | 값 |
|---|---|
| AI 작성 커밋 **302,600건 / 저장소 6,299개** 중 이슈를 1개 이상 넣은 비율 | **>15%** |
| 그 이슈 중 **최신 버전에서도 미수정** | **22.7%** |
| 살아남은 기술부채 총량 | 2025 초 수백 건 → **2026-02에 10만 건 초과** |
| AI 코드의 총 이슈 | 사람 코드 대비 **1.7×** |
| ├ 유지보수성·품질 오류 | **1.64×** |
| └ 로직·정확성 오류 | **1.75×** |
| 코드 중복 | **+81%** · 함수 간 연결성 **−35%** · 리팩터링 **역대 최저** |
| PR당 인시던트 | **+23.5%** · 리뷰 시간 **+91%** · AI PR 리뷰 대기 **4.6배** |

그리고 감사 업계 관측: *"2025–2026 감사에서 **AI 도구로 주로 만든 코드베이스는 예외 없이**
critical 또는 high 등급 발견이 **최소 1건** 있었다 — 어느 모델이 만들었든."* (2차)

경쟁 제품에 대한 평가도 같은 방향이다: *"이 도구들은 몇 시간 만에 **동작하는** 소프트웨어를
만드는 데는 비범하지만, **그것을 운영하는 데는 아직 신뢰할 수 없다.**"* (2차)

### 5.1 이 증거가 말하는 것과 **말하지 않는 것**

**말하는 것**: goppi가 겨냥한 격차 — *"동작한다"와 "유지·검증 가능하다" 사이* — 는
**실재하고, 측정됐고, 커지고 있다.** 그리고 **비엔지니어는 이 격차를 볼 수 없다.**
그들 눈에는 앱이 돌아간다. 부채는 보이지 않는다.

**말하지 않는 것**: **goppi가 이 격차를 줄인다는 증거는 여전히 0이다.**
문제가 실재한다는 것과 우리 해법이 듣는다는 것은 다른 명제다. worth는 `INCONCLUSIVE` 그대로다.

## 6. 이 최신화가 바꾼 것 / 안 바꾼 것

**바뀐 것**
1. 매니페스트 신설 필드 6종 — `renames`는 지금 넣는 게 싸다
2. Skills는 **오픈 표준**이 됐고 **조용한 이식성 상실**이라는 새 위험이 생겼다
3. **보안 축이 신설**됐다 (스킬 13.4% critical, 1차 확인) — 목적 ②의 근거 강화
4. **비엔지니어 시장에 자금력 있는 경쟁자가 있다** — "0/27"의 오독 방지
5. **양 프론티어 랩의 공통 처방 확보** — `{작은 상시계약 + 조건부 스킬 + 기계적 구조 검사 + git}`
6. **틀 강제의 수단이 바뀌어야 한다** — 런타임 훅이 아니라 **린터·구조 테스트**(§4.3).
   이것이 의존을 `🔴`에서 `🟢`로 옮기고 G1 오탐 문제를 함께 푼다
7. **문제가 실재한다는 측정값 확보**(§5) — 단, goppi가 푼다는 증거는 아니다

**안 바뀐 것**
- Skills 파일 규격 (PART IV §1과 일치)
- 컴포넌트 채택률 순위를 뒤집을 근거는 못 찾음 (재조사는 안 했다 — §7)
- 하네스 증강 패키지 범주 안의 "빈 칸 3종" 판정
  (다만 spec-준수 감사 칸은 **엔터프라이즈용 compliance 도구들이 부분 점유**한다.
   비어 있는 것은 **비엔지니어가 읽을 수 있는 형태**다 — 판정이 좁아졌다)

## 7. 이 기록이 보장하지 않는 것

- **n=27 전수조사를 다시 돌리지 않았다.** 원판은 27개 에이전트 병렬·617k 토큰이 들었다.
  이번엔 **표적 확인**만 했다. 채택률 숫자는 **2026-06-21 값 그대로**이며 재검증되지 않았다.
- **§3.3(보안)은 2026-08-08에 Snyk 원문으로 1차 확인했고, 그 과정에서 2차 인용의 오류를 잡았다**(100% → 100%/91%).
  **§2.2(오픈 표준)·§3.2(경쟁자)·§5(코드 품질)는 여전히 2차 다수 일치**이고 1차 원문 미대조다 —
  특히 §5의 수치들은 개별 연구의 표본·정의를 대조하지 않았으므로 **인용할 때 "2차"를 함께 적어라.**
