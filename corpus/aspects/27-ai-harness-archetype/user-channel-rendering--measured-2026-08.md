## 1. 무엇이 걸려 있었나

세션 #3은 게이트 응답을 두 청중으로 갈랐다 — 모델은 `permissionDecisionReason`,
사람은 최상위 `systemMessage`. 기계로 확인된 것은 **호스트가 `hook_system_message`라는
사용자용 전용 레코드를 만들고 그 내용이 모델 컨텍스트에 오지 않는다**까지였다.

그 레코드가 **사람 화면에 뜨는지**는 확인되지 않았다. 안 뜨면 goppi에게는 사용자 채널이
여전히 없는 것이고, 제품 주장("사용자가 감지할 수 있다")이 좁아져야 했다.

## 2. 절차 — 사전 등록

1. **기준선**: 이 세션 트랜스크립트의 attachment 종류를 세었다 → `hook_system_message` **0건**.
2. **발화**: G1을 한 번 고의로 발화시켰다. 평범한 리다이렉션 한 줄, 우회 없음.
   ```
   echo "OUTPUT-SURFACE render test 2026-08-08" >> /Users/coolbress/.goppi-harness/events/render-test.jsonl
   ```
3. **사람에게 물었다** — 발화 직후, 추가 명령을 하나도 실행하지 않고. 카운트를 정확히 1로 유지해
   "어느 발화를 본 것인가"가 모호해지지 않게 했다.
4. **교차 확인**: 트랜스크립트 재계수 · L3 이벤트 · 대상 파일 존재 여부.

## 3. 실측

### 3.1 사람이 본 것 (스크린샷으로 제출됨)

```
  Ran 1 shell command
  ∟ PreToolUse:Bash says: goppi가 명령을 막았습니다 — 검사 결과를 담는 기록 경로에
    쓰려는 것으로 판정했습니다. 검사를 받는 쪽이 그 결과를 고칠 수 없어야 하기
    때문입니다. 읽기는 막지 않습니다.
```

**렌더링된다.** 형태:

| 축 | 관측 |
|---|---|
| 위치 | 도구 호출 요약(`Ran 1 shell command`) **바로 아래, 별도 줄** |
| 글머리 | `∟` + `PreToolUse:Bash says:` — **훅 이름 레이블이 붙는다** |
| 접힘 | **접히지 않는다.** 도구 호출은 접힌 상태인데 이 줄은 펼쳐진 채로 보인다 |
| 색·아이콘 | 스크린샷 판독상 **전용 색·아이콘 강조는 보이지 않는다** — 도구 호출 요약과 같은 계열 |

### 3.2 부수 관측 — 두 청중 분리가 **화면 층에서도** 성립한다

기대하지 않았던 것: 모델이 받은 `permissionDecisionReason` 원문
(`"goppi G1: 하네스 증거 경로에 대한 쓰기로 판정했습니다 (write_redirect)…"`)은
**화면에 없다.** 도구 호출이 `Ran 1 shell command`로 접혀 그 안에 들어간다.

즉 **기본(접힌) 상태에서 사용자에게 보이는 goppi의 말은 사용자용 문장 하나뿐**이다.
설계가 의도한 분리가 데이터 층뿐 아니라 표시 층에서도 유지된다.

⚠️ 사용자가 도구 호출을 **펼치면** 모델용 원문도 볼 수 있다. 분리는 기본값이지 은폐가 아니다.

### 3.3 기계 교차 확인 — 4/4 일치

| 표면 | 결과 |
|---|---|
| 트랜스크립트 attachment | `hook_system_message` **0 → 1** |
| 그 내용 | 화면에 뜬 문장과 **바이트 동일**. `hookName: "PreToolUse:Bash"` · `hookEvent: "PreToolUse"` |
| 결속 | `toolUseID: "toolu_01EH7vsYLM3NPzfUGxc87gD8"` — 차단된 바로 그 도구 호출 |
| L3 | `2026-08-08T03:39:09.866Z gate_fired G1-LOG-WRITE decision=deny matched=write_redirect` |
| 파일시스템 | `render-test.jsonl` **부재** — 차단이 실제로 성립 |

읽기 경로도 같은 발화에서 확인됐다: 직후의 `ls`가
`harness_path_read G1-LOG-WRITE decision=allow`로 통과했다. G1은 쓰기만 막는다.

## 4. 판정과 처분

**`OUTPUT-SURFACE` 규칙의 만료 조건이 충족됐다** — "렌더링되면 verified 갱신, 안 되면 규칙 제거".
**렌더링되므로 규칙은 유지되고 `verified`가 승격된다.** spec §11에
"하네스는 사용자에게 직접 말할 수 없다"를 올리는 분기는 **발동하지 않는다.**

세션 #3 기록 §9의 첫 항목과 `progress.md`의 ⚠️ UNVERIFIED 문장이 해소된다.
이제 **"goppi가 사용자에게 말한다"고 쓸 수 있다** — 아래 §5의 범위 안에서.

## 5. 이 판정이 보장하지 않는 것

- **n=1이다.** 한 사람 · 한 터미널 · 한 호스트 버전 · **한 훅 이벤트(PreToolUse)**.
  세션 #3의 변이 A는 5개 이벤트 전부에서 `hook_system_message` **생성**을 확인했지만,
  **렌더링**을 확인한 것은 `PreToolUse` 하나뿐이다. Stop의 렌더링은 여전히 `UNVERIFIED`이고
  이는 G4 fallback 설계의 전제다(B21).
- **다른 클라이언트 표면은 미확인이다** — 데스크톱 앱 · 웹 · IDE 확장. 확인된 것은 터미널 CLI다.
- **눈에 띄는 정도(salience)는 측정하지 않았다.** 전용 색도 아이콘도 없다.
  이번엔 사용자가 **찾으라고 지시받은 상태**에서 봤다. 지시 없이도 눈에 들어오는지는 다른 질문이다.
- **읽혔는지·이해됐는지는 판정하지 않았다.** 제품 GO 7조건의 "이해 가능성"은 확증시험 소관이다.
  렌더링은 그 조건의 **전제**이지 충족이 아니다.
- **빈도·피로는 여전히 미측정이다.** G1은 조각 1에서 정당한 작업을 9회 막았다.
  채널이 실재한다는 것과 매 발화마다 써도 된다는 것은 다른 명제다 — §6을 보라.

## 6. 승격이 열어놓은 새 질문 — 채널이 생겼으니 이제 예산이 문제다

세션 #3까지 "정직 고지의 청중"은 **0개**였다. 이제 1개다. 그런데 그 순간
지금까지 물을 수 없었던 질문이 생긴다: **얼마나 자주 말할 것인가.**

- G1의 발화 중 **정당한 작업을 막은 것이 9회**(조각 1) + FP-2 재현 4회. 이 발화들에도
  사용자 문장이 붙는다. 오탐에 사용자를 부르는 것은 **채널을 태우는** 행위다.
- 반대로 발화를 줄이면 정직 고지의 목적 자체가 훼손된다.
- 현재 코드는 **모든 deny에 사용자 문장을 붙인다.** 이 선택은 데이터 없이 내려졌다.

→ 오탐 측정(조각 4 ADR-0032) 없이는 답할 수 없다. **미측정임을 명시하고 현행 유지**하되,
`OUTPUT-SURFACE`의 새 만료 조건으로 건다.

### 6.1 승격 판정 — **채널은 승격, 용도 확대는 보류**

인계문 ⓪의 분기는 *"보였으면 규칙 승격 + 정직 고지의 운반체로 쓸지 판단"*이었다. 판정을 나눈다:

| 대상 | 판정 | 근거 |
|---|---|---|
| `OUTPUT-SURFACE` 규칙의 `verified` | **승격** | 만료 조건이 실측으로 충족됐다 |
| 현행 용도(G1·G2의 차단·승인 문장) | **유지** | 이미 작동하고, 이번에 실물로 확인됐다 |
| **용도 확대**(G4 판정·완료 보고 등으로 넓히기) | **보류** | 빈도·피로가 `n=0`이다. 채널이 생겼다는 것은 **써도 된다**가 아니라 **쓸 수 있다**일 뿐이다 |

보류의 이유를 분명히 한다 — 이것은 소극이 아니라 **같은 규율의 적용**이다.
지금 용도를 넓히면 "사용자에게 더 많이 알린다"는 서술이 생기는데, 그 서술을 뒷받침할
측정값(발화 빈도 · 그중 오탐 비율 · 사용자의 반응)이 **하나도 없다.**
근거 없이 넓힌 주장은 spec §0.1의 판정 시험을 반대 방향으로 위반한다.

**용도를 넓히기 전에 필요한 것**: 조각 4의 오탐 분모. 그리고 `Stop` 이벤트의 렌더링 확인
(G4 fallback이 그 채널을 쓰려 하므로 — 이것은 다음 세션에서 기계로 확인 가능하다).

## 7. 이 절차 자체에 대해 — 사람에게 묻는 것이 유일한 수단이었다

세션 #1~#3은 **사용자 접촉 0**으로 진행됐다. 상위 모델이 지적한 미조치 3건 중 하나가 이것이고,
이 항목은 **자동화로 대체 불가능**했다. 헤드리스 자식 세션 10회로도 답이 안 나온 질문에
사람이 스크린샷 한 장으로 답했다.

기록해 둘 것: 인계문이 이 항목을 **⓪번, "미루면 또 안 한다"**로 적어놓지 않았다면
이번에도 밀렸을 것이다. 세션 #3이 자기가 못 하는 일을 **다음 세션의 첫 항목으로 못박은** 것이
작동했다.
