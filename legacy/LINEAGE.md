## 2. 하나의 목적이 다섯 번 다시 시도됐다

다섯 하네스의 문장은 표현만 다르고 같은 것을 말한다.

- **claudeck-v1**: *"Your command deck for vibe-coding with Claude Code."* — ⚠️ 이 한 줄만으로는
  아래 세 판과 **같은 목적인지 논증되지 않는다.** v1의 서술은 *도구의 성격*을 말하고 나머지는 *사용자의 처지*를
  말한다. 편입(2026-08-24) 후에도 이 절은 그 차이를 해소하지 못했다 — **열린 질문으로 둔다.**
- **claudeck**: *"npm으로 배포되는 Claude Code 하네스 — 마켓플레이스로 설치되는 플러그인 + 온보딩 CLI"*
- **gingoa**: *"비엔지니어의 아이디어를 시니어급·프로덕션급 소프트웨어로 이끄는 교차호스트 하네스"*
- **goppi_final**: *"엔지니어링을 모르는 사람이 아이디어만 주면, 에이전트가 현업 개발 과정을 조율하되
  사람이 해야 하는 단계는 안내하고, 판단이 정말 필요한 순간만 회부한다"*

**목적은 한 번도 바뀌지 않았다.** 바뀐 것은 그것을 어디에 지을 것인가였고, 다섯 번 다 같은 자리를 골랐다 —
**에이전트 안쪽**(플러그인·훅·스킬).

## 3. 각각이 무엇을 시도했고 왜 죽었나

### claudeck-v1 (~15일 · 190커밋 · 272파일) — 원조이자 **가장 큰 판**

**시도**: 최초 커밋이 방향을 그대로 말한다 — *"genesis — **version-control the global Claude Code
harness as a portable dotfiles repo**"*(2026-06-05). 전역 `~/.claude`를 통째로 버전 관리하는
휴대 가능한 dotfiles 저장소로 만들고, 거기에 훅·에이전트·스킬·평가 벤치를 쌓았다.
README의 한 줄: *"Your command deck for vibe-coding with Claude Code."*

**규모**: 272파일 — `hooks/scripts` **52** · `scripts` 37 · `docs` 18 · `agents` 8 ·
`eval/review-bench`(적대 픽스처 포함) · `eval/routing-bench` · `templates/github/ISSUE_TEMPLATE`.
**5세대 중 커밋이 가장 많다(190).** 첫날에만 6커밋으로 의존성 자동설치·핀 드리프트 감지·
`githooks/pre-push` 정합 게이트(`harness-doctor`)를 세웠다.

**하네스 지식의 외부화**: 학습을 **프로젝트에 묶이지 않는 파일**(`harness-notes.md`)에 축적했다 —
*"자동 메모리는 프로젝트별(per-cwd)이지만 하네스에 관한 학습은 프로젝트 무관이므로 여기 산다."*

**남긴 것**: 이후 모든 판이 인용한 관찰 두 가지 —
① **서브에이전트에 중간 권한 릴레이가 없다**(승인 안 된 도구를 집으면 *에러가 아니라 짧은 보고서*를 반환)
② 하네스 지식을 **세션 밖 파일로 외부화**한다는 발상. goppi P5(상태 외부화)의 조상이다.

**사인**: npm + 플러그인 마켓플레이스라는 업계 표준 배포 경로로 **재플랫폼하기로 결정** → claudeck.
저장소는 이후 삭제됐고(원격 404), 노트만 `sources/claudeck-v1/`에 남았다.

⚠️ **이 세대는 계보 첫 판에서 누락됐고, 두 번째 판은 수치를 틀리게 적었다** —
둘 다 소유자 지적(2026-08-24)으로 시정됐다. 세 번째 판인 이 서술만이 `~/Archive/claudeck-v1.git`
**실사에 근거한다.** 나머지 272파일은 `git show HEAD:<path>`로 추출할 수 있다.

**흥미로운 사실 하나**: v1은 이미 `githooks/pre-push` 정합 게이트와 `eval/review-bench` 적대 픽스처를
갖고 있었다. 즉 **"검사를 자동화하고 적대적으로 시험한다"는 발상은 첫 판부터 있었다** —
78일 동안 바뀐 것은 그 검사를 **어디에 두느냐**였다(`direction/02` 진단 1).

### claudeck (2일)
**시도**: 원래 하네스를 npm + 플러그인 마켓플레이스라는 업계 표준 배포 경로로 재플랫폼.
**남긴 관찰**: 서브에이전트에 **중간 권한 릴레이가 없다** — 승인 안 된 도구를 집으면 조용히 *짧은 보고서*를
반환한다(에러가 아니라). 이 관찰은 이후 모든 판에 인용됐고, 지금도 `legacy/sources/claudeck-v1/harness-notes.md`에 있다.
**사인**: 재플랫폼 도중 더 넓은 설계(gingoa)로 방향 전환.

### gingoa (17일)
**시도**: Claude Code + Codex 양쪽에 붙는 공유 코어 + 호스트별 어댑터. ADR 21건으로 아키텍처를 고정.
**진짜 산출물**: `docs/research/` — **28측면 근거 코퍼스**. SWEBOK·ISO 12207·25010에 앵커된 이 코퍼스가
gingoa가 남긴 유일하게 살아남은 것이고, **지금 이 저장소의 `corpus/`가 그것이다.**
**사인**: 28측면 전부를 다루려다 범위가 폭발. CLI는 끝내 배포되지 않았다.

### goppi (15일)
**시도**: 3층 구조 — 상시 계약 / 조건부 스킬 / 결정적 바닥. 결정 42건. 하네스 자체를 평가하는 `evals/` 도입.
**핵심 판단들**: *"모델이 제안하고 기계가 검증한다"*(ADR-0007), *"안전 비대칭 — 작업 가드는 열려 실패하고
보안 통제는 닫혀 실패한다"*(ADR-0008), *"다중 모델 디스패치는 라우터가 아니라 로스터"*(ADR-0019).
**마지막 결정이 사인을 예고했다** — ADR-0041: *"규칙에는 운반체와 게이트가 필요하다 —
**모델이 닿을 수 없는 규칙은 규칙이 아니다**."*
**codex-native 시도**: ADR-0023 *"Full codex-native replacement — capability matrix, absorption,
behavior-level dual-host"* 는 **별도 하네스가 아니라 goppi 안의 결정**이었다 — Claude Code와 Codex
양쪽에 같은 계약을 태우되 호스트별 어댑터가 아니라 **행동 수준의 이중 호스트**로 가겠다는 것.
gingoa의 ADR-0001(교차호스트 공유 플러그인)에서 이어진 계보이고, goppi_final에서는
**호스트를 Claude Code 하나로 좁히는** 소유자 결정(2026-08-03)으로 되돌려졌다.

**사인**: 층이 서로를 지탱하지 못하고 자기 무게로 붕괴. goppi_final로 재시작.

### goppi_final (16일) — 유일하게 자기를 시험한 판
**시도**: 범위를 walking skeleton 하나로 줄이고, **게이트가 실제로 작동하는지 측정**.
**한 일**: L0 상시 계약 + G1(증거 경로)·G2(위험 명령 승인)·G4(완료 검증) + L3 계측.
실물 확증시험 2세션. Codex 교차벤더 적대 리뷰 다수. 기록 56건.
**사인**: **확증시험이 하네스의 실패를 증명했다.** 아래 §5. 이건 붕괴가 아니라 **결론**이다.

### 왜 미완인가

**느낀점은 소유자만 쓸 수 있다.** 위 여섯은 *기록에 우연히 남은 조각*이지 회고가 아니다.

확증시험 결과(11건 침묵·오탐 67%)를 처음 봤을 때의 반응, 그리고 78일을 돌아본 지금의 소회.
