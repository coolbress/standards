## Repo architecture — why claudeck is shaped this way (L2, 2026-06-05)

`~/.claude` is version-controlled as the **private** repo `coolbress/claudeck`. The
decisions below are recorded here (a *tracked* file) on purpose: the auto-memory that
drove this build is per-machine and gitignored, so this section is the **portable**
record of the rationale. (Full blow-by-blow lives in a gitignored hub scratch doc,
which does NOT travel — treat this as the durable summary.)

- **Distribution = adopt-in-place (whole-dir clone, not plugin/marketplace).** The repo *is*
  `~/.claude`; an existing `~/.claude` is turned into a checkout **in place** (personal state
  is gitignored, so nothing is lost), a fresh machine clones it there, then `bootstrap.sh`.
  Why whole-dir and not a plugin (+ the future hybrid path) → [`distribution-model.md`](distribution-model.md).
- **Pure harness — user-independent ∧ project-independent.** No project names / beliefs /
  domain coupling in tracked files. Adapt along two layers: *machine layer* (host deps,
  MCP, env via `bootstrap.sh`, once per machine) + *project layer*
  (`<repo>/.claude/harness.conf` + the project's own `.github/`, once per project via
  `/harness-init`). The doctor's L3 self-skips when a repo ships no `harness.conf`.
- **Memory is NOT tracked (decision D1, reversed from an earlier plan).**
  `projects/**/memory/` stays gitignored — personal/project working-state must not ride a
  universal harness repo. Anything the harness *functionally* needs is baked into tracked
  tools, never memory. **Consequence:** memory has no remote backup, so durable decisions
  graduate **into this doc**, not into tracked memory.
- **Allowlist `.gitignore` (fail-closed).** `/*` ignores everything, then `!`-re-includes
  only the engine dirs/files; `**/__pycache__/` + secret globs are hard-re-ignored LAST.
  Any future ephemeral/secret dir Claude Code adds is excluded by default (≠ committable).
- **`$HOME`-portable settings (D5).** `settings.json` hook commands use `$HOME/.claude`,
  not a hardcoded `/Users/<name>` — Claude Code shell-expands `$HOME` at load.
- **Two git gates, separated by altitude.** `githooks/pre-commit` = **secret** gate
  (`gitleaks git --staged`, every commit, fail-closed). `githooks/pre-push` = **correctness**
  gate (full `harness-doctor`, once per push, blocks only on hard ERROR). Both wired by
  `core.hooksPath=githooks` (bootstrap sets it; per-clone, never pushed).
- **Dependency subsystem (package-manager pattern).** `bootstrap-assets/Brewfile` +
  pinned `npm-globals.txt` + `HARNESS_DEPS.md`; `bootstrap.sh` installs them; **doctor L3**
  flags pin drift. Turns "mystery breakage after a CLI upgrade" → "doctor flags drift →
  re-run bootstrap".
- **GitHub templates: project-first resolution (D6).** `templates/github/` ships a generic
  master; the `github-workflow` / `pr` skills read the project's own `.github/` if present,
  else fall back to the master; `/harness-init` scaffolds them into a repo (no-clobber, so
  the project always wins). This makes the harness work on a repo that has no `.github/`.
- **No cloud CI — local `pre-push` instead (item 2; cloud GitHub Actions declined).** On a
  solo / private / unenforceable (Free plan = no branch protection) / platform-skewed (harness
  runs on darwin, ubuntu runners false-red the macOS-coupled tests) repo, cloud CI is an
  advisory signal that rots. The correctness gate runs on the **actual target platform for
  free** via pre-push. Reconsider only if claudeck goes public / multi-contributor. Decision
  rule: **CI/PR value ∝ (mechanical testability) × (contributors) × (enforceability) ×
  (blast radius)** — fit-for-purpose, not maximal ceremony.
- **PR flow.** For **claudeck itself** = commit-to-`main` behind the two gates (the standard
  for a solo dotfiles repo; full issue→PR→review ceremony would be over-fit). The full
  issue → branch → PR → review-round → merge pipeline is for the **product** repos the
  harness *operates on* (e.g. any product repo), not for the harness repo.

## gitnexus auto-indexing — DECISION: strip the per-edit/per-commit reindex storm; keep deliberate-query + a SessionStart single-flight build ("stripped-A", decided 2026-06-17, IMPL COMPLETE 2026-06-18)

**Decision (3-party Claude+Codex+architect panel, converged over 3 rounds — 1:1 split → unanimous):**
keep gitnexus's **deliberately-invoked** query tools (`impact`/`query`) **and a SessionStart single-flight
build**, but **remove the per-edit / per-commit automatic indexing** — the reindex *storm* (the two
PostToolUse spawn doors). **NB (precision):** this is *not* "remove ALL automatic indexing" — the
SessionStart `gitnexus-autobuild.sh` build is **retained** (see layers 1–2 below); what was cut is the

rebuild. This is the 4th OOM source the reapers above couldn't see (indexers aren't agents/MCP).

**Why (all MEASURED 2026-06-17, 8GB host):**
- **Cost = a reindex STORM.** Two unguarded spawn doors: `gitnexus-reindex.sh` (PostToolUse every

single-flight lock was keyed **per-worktree**, so N worktrees session-starting at once could fan out into N
concurrent ~1.5GB indexers, and the `/graph` viewer ran the indexer with **no lock at all**; and that lock
released only via `trap EXIT`, so a SIGKILL'd holder wedged the worktree into permanent `SKIP-LOCKED`. Both the
autobuild (replacing its per-worktree lock) and the `/graph` viewer (policy Ⓐ: lock held → skip refresh, serve the
existing graph a tick stale) now run their indexer through **one host-global, cap-1** admission lock. **Final
design = mkdir-only, NO steal** (mkdir is the only portable atomic op; macOS has no `flock(1)`). An in-path "steal
a stale lock" is fundamentally racy — the liveness check and the destructive removal/rename can't be made atomic
in portable shell, so a racer can stamp a fresh LIVE lock in the gap and have it destroyed → two indexers. Five
review rounds **plus a 3-party review (lead + internal Opus architect + external GPT-5) that REPRODUCED a
double-run 113/400 trials** confirmed every steal variant (rmdir-then-mkdir, `mv`-rename, a 2nd reclaim mutex, a
TTL/age ceiling) reintroduced the same ABA. So acquire is a SINGLE atomic `mkdir`; cap=1 then holds TRIVIALLY
(one winner; the only removals are **owner-mark-gated** and act only on our OWN lock, so no caller can destroy
another's). Plus: **host-global path** = uid-tagged `/tmp`, not `$TMPDIR` (per-session on macOS → would defeat the
cap); **checked stamp** (a failed owner/pid write releases the provably-ours dir + skips, never runs lock-less).

leaving a stale lock that — with no steal — is never auto-reclaimed, so indexing SKIPS (graph goes stale) until
`/tmp` clears on reboot or a one-line `rmdir`. Post-storm a lone capped indexer is unlikely to be OOM-killed, and
a stale graph beats a steal that can run two indexers. **Supersedes the layer-2 "per-worktree mkdir lock"**
(`gitnexus-index-lock.test.sh`: 12 cases incl. a `20×6`-racer stress proving exactly 1 admit/trial, and a stale
lock that 6 racers all skip); autobuild only decides SKIP-FRESH vs WOULD-BUILD. Net: the storm source is
structurally gone AND the last burst vector is closed under one tested primitive; the only steady-state occupancy
is small (~6MB) attribution-gated MCP/broker helpers, reaped at session boundaries (Tier-3 live-parented ones
spared) — no leak.

## Design principles crystallized (2026-06-11 — harness⊥project separation + guard/review session)

Durable principles distilled from a long separation/cleanup session (commits are the 1st record; these are the *reusable* rules, not the blow-by-blow):

- **Harness ⊥ project — the *project-side* test.** §"Pure harness" above covers the harness side (no project coupling in tracked files); the dual rule for a PROJECT doc: it may hold only **[project-independent info] + [info the harness READS to function]** (`harness.conf` fields, the plan-template's machine fields, `make` targets the hooks call). Litmus: *"if the harness changes, does this project doc go stale?"* → yes ⇒ it's misplaced harness mechanics, move it OUT. Concrete (fyan cleanup 2026-06-11): a project's `docs/AGENTS.md` re-documenting routing/dispatch/tier rules, a `RULES.md` paragraph re-explaining the `wt-create-lead-head.sh` hook, a `QUALITY_SCORE.md` "code-reviewer agent" checklist item = all drift traps → removed. **Distinguish from `.github/` issue/PR templates, which ARE legitimately project-first** (issue fields genuinely differ per repo — keep their override). The "use gitnexus to navigate" *practice* is harness-owned (lives in the auto-loaded `routing-summary.md`); a project's CLAUDE.md documents only its OWN graph setup (`make gitnexus`, indexed paths, repo-name gotcha). Before this, `implementer.md` back-referenced "CLAUDE.md's query-the-graph guidance" → a project doc was **load-bearing** for harness navigation behavior (the smell that flags misplacement).
- **Plan template = single canonical harness SSOT — no project override.** `writing-plans` dropped the "use the project's `docs/_templates/exec-plan-template.md` if it ships one, else the internal structure" branch — that override is exactly what let a project ship a drifted partial-copy (fyan's was **missing the required `[complexity:]` dispatch label** → its tasks would silently fall through to Sonnet). A code plan is generic engineering workflow; authors extend a plan *instance* with project-specific sections, never fork the template. (Senior-review add-ons, all optional: `Depends:` = explicit task-DAG that `[parallel-safe]` derives from; `Risks & Assumptions` for tier-3/high; `Undo:` for irreversible tasks; outcome-based sizing — "smallest independently-verifiable unit" — replacing the human "2-5 min/task" that invited over-fragmentation.)
- **Don't add context-dependent permissiveness to a security control** (subagent guard-block, 2026-06-11). A *dispatched subagent cannot add `# user-confirmed`* (no user to approve) → a legitimately-needed destructive command surfaces to the LEAD (`implementer.md`/`simple-executor.md` carry a safe-alternative table: revert→Edit-forward not `git checkout`/`reset --hard`; clean→`rm -r`/`rm -f` not `rm -rf`/`find -delete`; hung proc→graceful `kill` not `-9`). A **worktree-aware RELAXATION** (allow destructive ops because a subagent's worktree is disposable) was **REJECTED**: cwd≠op-target (an abs-path / `cd elsewhere` / symlink escapes the worktree; `push`/`kill` are global anyway), so it bolts a *false-relax* failure mode onto a fail-safe control. Asymmetric cost decides it: a false-block = one escalation (mild, recoverable); a false-relax = the catastrophe the guard exists to prevent → **uniform conservatism + escalation beats clever context-gating** on a security boundary. The residual "legit-but-blocked in a no-user context" is ~zero AND the few that remain (full discard, `kill -9`) are ops that SHOULD be human-gated.
- **The guard has TWO KNOWN/ACCEPTED boundaries** (same backstop-not-adversarial-sandbox rationale as the bullet above + §Closed-audits R-cont4; real containment = worktree isolation + native deny). Axis 1 = *evasion-breadth* (contrived obfuscation; §Closed-audits R-cont4). Axis 2 = *verb-breadth* (NEW, official-LOCK Rounds 2–3): the COMMON destructive verbs are now all covered — `rm -rf` · `find -delete` · `truncate -s0` · `dd of=` · `shred` · git `reset --hard`(deny)/`restore`/`checkout --`/`switch --discard`/`branch -D`/`push --force|--mirror|+ref`/`clean -fd`/`stash clear|drop`/`gc --prune=now`/`reflog expire`/`prune` · `kill`·`pkill`·`killall` SIGKILL (every spelling, IGNORECASE) · SQL `DROP`/`TRUNCATE`; the obscure long-tail (`mkfs`, `>file` truncation, `filter-branch`, `chattr`) is diminishing-return, accepted. Don't chase EITHER axis to completeness (architecturally impossible for a string scanner). (Companion: `secret-leak-guard` now also scans `NotebookEdit`'s `new_source`, and a boundary-anchored bare `token=` that won't false-flag `csrf_token`/`raw_token`.)
- **Two review-consolidation topologies — match to goal, never unify.** `/audit` = **independent-parallel critics** (P1 ∥ P2, context-isolated) → lead **unions + adjudicates by code-citation** (Delphi: independence maximizes COVERAGE, anchoring is harmful, the USER is the final arbiter via R5/R9, unbounded rounds). `review-round` = **proposer(R1)→adjudicator(R2) CHAIN** (R2 is dispatched WITH R1's findings → confirm/adjust/drop, R2's call is FINAL): optimizes PRECISION (a dedicated pruner kills R1 false-positives on a bounded PR diff) + deterministic id-merge + cross-round oscillation tracking + the EXTERNAL model (Codex) holds the last word = **max vendor-diversity at the decision point**. The chain is sequential by genuine **data-dependency**, NOT stale hand-serialization — making it Delphi would trade away precision/determinism/vendor-diversity for marginal coverage on an already-small diff. Same two agent *types* (`code-reviewer`+`cross-checker`), opposite dispatch (parallel in audit, sequential in review-round) — that is correct, not an inconsistency. (Corollary, also fixed this session: *independent* panels — the audit pair, multi-`researcher` sweeps, parallel implementers — dispatch as ONE parallel batch and let the weighted semaphore arbitrate; do NOT hand-serialize them. The earlier "8GB→1 serial" doc wording was stale vs the weighted-budget reality — light agents (`code-reviewer`/`cross-checker` = 1GB) run 2-up under the 8GB BUDGET=3.)

- **DIM-3 ALLOW-side — the legit-but-blocked fix is `permissions.allow`, never broad Bash prefixes (2026-06-11).** Complement to the block-side rule above: a dispatched subagent that hits an un-pre-approved tool is **denied/aborted, never relayed to the user** (see the platform-gotcha below), so a *legitimate* tool a background agent needs must be pre-authorized **session-wide** (allow rules are inherited by subagents — the documented, platform-native lever). The ONE reproduced false-block (a `researcher` subagent's WebSearch/WebFetch) was fixed by adding `WebSearch`+`WebFetch` to `permissions.allow` (`0ea447e`). **Two things were investigated and REJECTED — both for necessity reasons:** (a) allow-listing read-only Bash prefixes (`Bash(grep:*)` …) = a **no-op** — CC already auto-approves its built-in read-only set (`grep/cat/ls/find/head/tail/wc/diff/git-read`) "in every mode" *including the `>file` redirect form* (live-probe confirmed), so the rule adds nothing; (b) hardening `bash-tool-redirect.sh` to block reader-command `>file` truncation = **breaks current functionality** — a full-transcript census found the dominant real reader-redirect is **subagents authoring test files via `cat > tests/*.py <<'PYEOF'` inside their worktree (37 calls)**, while the footgun it would defend (`reader FILE > sameFILE` clobber) has **0 occurrences ever** → defending a 0-incident theoretical risk by breaking a live TDD pattern is the necessity-before-maximization anti-pattern. The `gitnexus analyze` check has a head-based carve-out (`head in {grep,cat,python3,…}` ⇒ treat as quoted literal), but it must **NOT** be copied to the destructive checks. PROVEN unsafe: a compound `cat <<'EOF' … EOF && rm -rf /tmp/x` (and `… ; git branch -D main`) starts with `cat` (∈ data_ctx) → a head-based carve-out would SKIP the destructive checks and ALLOW the REAL `rm -rf` / force-delete after the heredoc = guard defeated. Cost asymmetry justifies the fail-safe over-block: false-positive = one `진행해줘` (friction); false-negative = catastrophe. The carve-out is acceptable for `gitnexus analyze` only because its worst case (doc injection) is non-catastrophic/recoverable. The ONLY safe in-guard fix would be heredoc-**body** stripping scoped to non-interpreter consumers (must exclude `psql`/`python`/`sqlite3` heredocs whose body genuinely executes — verified: `psql <<'EOF' DROP TABLE EOF` is a true-positive), i.e. a non-trivial parser with its own false-negative risk — **declined, not worth it.** **Go-forward (the real fix is behavioral):** write file content containing dangerous strings via the **Write tool**, not a Bash `cat`/`tee` heredoc (already the harness-preferred pattern — the system prompt deprecates `cat`/`echo`-via-Bash for file writes; the guard is nudging toward it). **Applied 2026-06-09 (`cross-checker.md` Step 2a):** audit-mode Codex `task` now passes its prompt via `--prompt-file` (written with the Write tool) instead of an inline arg — the forwarded audit *ledger* quotes dangerous literals when the scope is the guard / security code, which the inline form put on the command line → the guard blocked the `node` invocation → Codex silently degraded to Sonnet self-adjudication (Codex blocked by the very guard it was reviewing). 2b `adversarial-review` stays inline (positional-only; supports neither `--prompt-file` nor stdin) — safe because it reads the diff from git, so no subject text rides the command line. (memo: `reference-codex-plugin-local-patches` Patch 3.)
- **gitnexus project-file scaffold: ONLY `analyze` does it — `mcp` and `setup` do NOT (verified gitnexus 1.6.5, 2026-06-11; kills a recurring false-finding):** the only path that writes `CLAUDE.md`/`AGENTS.md`/`.claude/skills` into the PROJECT (cwd) is a bare `gitnexus analyze` (full) — and that is **guard-blocked** (`dangerous-command-guard.py`, exit 2; the 3 hooks autobuild/reindex/.cjs all use `--index-only` = AST-only, no writes). **Do NOT re-attribute the scaffold to the MCP server:** `gitnexus mcp` is **serve-only** ("serves all indexed repos" — reads the global index registry; it has no analyze capability and no `--index-only` flag to even add). Empirical proof it doesn't scaffold: a repo can be freshly *indexed* (by the `--index-only` autobuild hook) yet have **zero** scaffold files. `gitnexus setup` writes **exclusively under `os.homedir()`** (`setup.js`: every base is `os.homedir()/{.claude,.cursor,.codex,.config/opencode,.agents,.claude.json}`, **zero `process.cwd()`**) → it configures GLOBAL editor MCP/skills, never the project repo. So the project-injection concern is fully closed by the one `analyze` guard; the "MCP/setup injects into the project on rebuild" theory is a **mis-attribution** (cost ~5 round-trips on 2026-06-11 before source-tracing settled it).
- **secret-leak-guard does NOT scan Bash command argv (2026-06-08):** the guard covers `Write|Edit|MultiEdit` content only (the doctor L2 matcher check enforces that), NOT Bash commands — so a secret passed as a CLI arg (`grip … --pass "$GITHUB_TOKEN"`) slips past it. Worse, a `$VAR`-passed secret is **undetectable pre-expansion** anyway (the hook sees the variable name, not the `gho_…` value; only the runtime argv / `ps` / the session log hold the literal). gitleaks still catches a *literal* secret at commit, but not one in a run-only ad-hoc command. **Go-forward (behavioral, not a guard change):** never pass a secret as a command-line argument — use the tool's own env vars / config (grip: `GRIP_USER`/`GRIP_PASSWORD`) or run without auth; if one reaches `ps`/a log, rotate it. A literal-secret Bash backstop was **declined** — it can't catch the `$VAR` vector, the literal case is already covered by gitleaks, and it adds false-positive cost. (memory: `feedback-no-secrets-in-cli-args`.)

- **No mid-subagent permission relay — pre-authorize or it aborts (2026-06-11, official-doc confirmed):** a dispatched subagent (Task/Agent) runs with **"independent permissions"** (sub-agents doc) inherited from the session; when it hits an un-pre-approved tool there is **no "subagent → user → subagent" interactive approval round-trip** — in any non-interactive context "**the run aborts when one is attempted**" (headless doc; `dontAsk` "denies anything not in `permissions.allow` or the read-only command set"). The only inter-agent feature, *agent teams*, is session-to-session **messaging**, not a permission relay. The COMPLETE set of subagent permission control points = (1) inherited `permissions` allow/deny/ask, (2) per-subagent `permissionMode` frontmatter, (3) PreToolUse hooks, (4) the `tools`/`disallowedTools` ceiling. ⇒ the platform-native pattern is **pre-authorization + task-boundary review by the lead**, never a per-tool relay — don't design one.

## Hook & worktree contracts (preserve these; known gotchas)

Each fact is stated ONCE here (it was triplicated across the old "Recently-tightened / Operational
gotchas / Patterns NOT to repeat" sections — the same hook facts in preserve / gotcha / anti-pattern
framings; collapsed 2026-06-16). Full diff → `hooks/scripts/CHANGELOG.md`.

- **cherry-pick-cleanup.sh — use shlex, and `CHERRY_PICK_HEAD` is the authoritative signal.** SHA
  extraction uses Python `shlex` (quote / separator / command-position aware; the FU-1 trailing-separator
  bug is regression-tested in 22 cases) — do NOT regress to `sed | tr | grep` (loses that awareness). Run
  `git cherry-pick <SHA>` on its OWN line: in a compound `git cherry-pick X; <other>` the `exit_code` can
  be masked, so the hook keys on the **`CHERRY_PICK_HEAD` ref**, not `exit_code`, to detect a
  conflict-state worktree — never trust `exit_code == 0` from a chained cherry-pick.
- **wt-remove-cleanup.sh removes the worktree+branch+dir on ExitWorktree.** Claude Code's own
  ExitWorktree(remove) is a **no-op on disk** (verified 2026-05-25), so the WorktreeRemove hook is what
  actually cleans up — don't assume the runtime does it.
- **wt-create-lead-head.sh forks every agent worktree from the lead session's HEAD** (envelope `cwd`),
  overriding the runtime default (which resolves `baseRef:"head"` from the common-dir PARENT = the hub).
  **Required regardless of bare-vs-non-bare hub** (the default walks to the common-dir parent independent
  of `core.bare`; without the hook an agent dispatched from a feature worktree forks from the hub's `main`
  and loses the lead's unmerged commits — the "only for a bare hub" hypothesis was refuted by probe). Full
  detail = the §Shipped-subsystems "baseRef (single-location base) + base-effect check" row.
- **`git branch -D worktree-*` is disposable by convention — exempt from the guard, but the regex is
  literal-text.** dangerous-command-guard exempts `git branch -D worktree-*` (covers agent + EnterWorktree
  worktrees) and the harness RELIES on being able to delete them — do NOT hard-block them. But the
  exemption is literal-text-matched, so a shell-variable target like `git branch -D "$b"` is BLOCKED (the
  literal is the variable token, not `worktree-*`) → bypass with a `# user-confirmed` marker when sweeping,
  or expand the variable before invoking.
- **Agent-worktree isolation self-check.** `implementer.md` / `simple-executor.md` require
  `git branch --show-current` to start with `worktree-agent-` BEFORE the first commit; if not, the agent
  STOPs and reports BLOCKED (an isolation breach = committed to the lead branch instead of its worktree).
- **A BLOCKED + uncommitted agent worktree is NOT auto-cleaned** by the runtime (despite docs implying
  so) — run the `executing-plans` "safety-net sweep" at the end of any plan with possible BLOCKED tasks.
- **session-start-test-smoke.sh runs `run-all-tests.sh` on every SessionStart** — a startup warning is a
  real regression; investigate before proceeding.
- **PostToolUse Bash hook chain ≈ 164ms/call** (2026-05-25 baseline `echo hello`); most of it is Python
  startup (each hook calls python3 once to parse JSON). Batch parsing if it becomes a felt slowdown.
- **codex-companion (the external GPT review pipeline)** — `cross-checker.md` wraps it in two modes:
  **review-round** = `adversarial-review --scope branch` (360s, reads the git diff); **audit** = diff-free
  `task` (1500s) via the `AUDIT-SCOPE-MODE` sentinel (since `21053be` — `adversarial-review` starved on a
  clean audit scope and silently *discarded* Codex's findings = the F16 bug). 1 retry re-runs the SAME
  Step-2 command verbatim (keeps the `--model gpt-5.5` pin → also fixed H1's drifting retry); partial
  output preserved at `/tmp/codex-cross-check-last.out` (mine it if a run silently fell back). On CODEX
  UNAVAILABLE the harness still proceeds (advisory; review-round degrades to Sonnet self-adjudication,
  marked in `status`).
- **Codex model-selection differs by role — by design, not drift.** `cross-checker` **pins**
  `--model gpt-5.5 --effort high` (it is a *gating adjudicator* in review-round/audit → must be
  reproducible, independent of config). `codex-consult` leaves `--model`/`--effort` **unset** → inherits
  `~/.codex/config.toml` (currently also `gpt-5.5`/`high`) so the *advisory* second-opinion follows the
  user's own Codex config. Same value today, **different mechanism on purpose** — gating⇒pin,
  advisory⇒user-controlled; don't "align" them. Escape hatch: a high-stakes deliberation can pin
  codex-consult for one run by naming the model explicitly in the lead's forwarded prompt.
- **Fixed-path Write-staging must `rm -f` BEFORE the Write (the staging-clear class).** Any agent/skill
  that stages a prompt/body to a FIXED `/tmp` path consumed via `--prompt-file`/`--body-file` must clear
  it first: the Write tool refuses to overwrite a file not Read this session, so on the 2nd use the new
  content silently fails and the consumer ships the PRIOR run's stale content (codex-consult re-answered a
  cached prompt; a 2nd PR would publish the 1st PR's body). 4 sites: codex-consult, cross-checker, pr,
  github-workflow. Enforced for present+future sites by ONE generalized lint `staging-clear.test.sh`
  (placeholder/`$VAR` paths auto-exempt — unique per call); per-site checks were deduped into it
  (2026-06-18, commits `f5109f1`→`8dd99b3`). Subagent sites are the dangerous ones (they ignore the loud
  Write error → silent staleness); lead-run skills surface the error loudly → self-correct.
- **Cleanup disposal predicate (`scripts/plan-landed.sh`) — durable-key ladder, FAIL-OPEN to KEEP
  (2026-06-18).** `/cleanup` no longer gates plan deletion on "PR merged"; it gates on *"is the plan's
  work durably on `origin/main`?"*, decided live by the tested `plan-landed.sh`. It walks a **durable-key
  ladder** highest-rung-first — **PR rung** (`pr:` → `gh pr view` MERGED **+** `mergeCommit.oid`
  is-ancestor `origin/main`) → **Plan-Id rung** (`plan_id:` → *every* commit carrying the `Plan-Id: <id>`
  trailer is-ancestor `origin/main`) — proving landing the ONLY durable way: SHA-ancestry to origin/main.
  This is the **structural inverse of `verify-agent-base.sh`**: same primitive trio (identity-anchor +
  ancestry + `norm()`), opposite default — verify-agent-base fails **CLOSED→BLOCK** (its risk is a wrong
  cherry-pick), plan-landed fails **OPEN→KEEP** (its risk is a wrongly-*deleted* plan = unrecoverable
  working memory). ANY uncertainty (offline/stale fetch, shallow, no origin/main, unresolved SHA, PR not
  merged, trailer absent, **one unshipped unit pins the whole plan**) → KEEP, never a false delete. The
  enabling label is the **`Plan-Id` git trailer** ([[writing-plans]] mints `plan_id:` WORM at plan-start;
  [[commit]] auto-appends it to no-issue/direct-to-main commits): *backward-stable* — it lives INSIDE the
  message so it survives squash/rebase/amend, where a forward shipped-SHA pre-stamp would rot. **C (a
  mutable integration-branch "already-landed" shortcut) was deliberately DROPPED** — a branch tip is not
  durable landing. Design locked via two 3-party deliberation rounds (Opus + Plan + codex-consult GPT-5);
  both independently flagged bare `--is-ancestor` (squash-unsafe). Files: `scripts/plan-landed.sh`
  (+`.test.sh`, doctor L4) · `skills/cleanup` · `skills/writing-plans` · `skills/commit`.
- **Cleanup discovery ⊥ deletion + structured disposal-plan (2026-06-18).** Closes the two boundaries
  the predicate left: (1) **discovery is automated, deletion stays manual.** A SessionStart hook
  `cleanup-cleanable-notice.sh` runs `plan-landed.sh --quick` over `plans/` and surfaces *"N plan(s)
  look cleanable — run /cleanup"* — it **NEVER deletes or runs anything** (the y/N + fail-open human-pin
  are untouched). This is the anti-stale fix: make landed-but-uncleaned plans *visible* without
  auto-acting. `--quick` is **network-free** (no `git fetch`, no `gh` — PR rung defers to the real
  /cleanup); it may UNDERCOUNT (fail-quiet) but never overcounts. (2) **the predicate now emits
  `STEPS=`** — the structured disposal-plan (`metrics,worktree,branch,plan,workspace` filtered by which
  anchors exist), so `/cleanup` runs a **checklist + one consolidated preview** instead of re-deriving
  null-safety from prose (same "extract the predicate, don't hand-retype it" principle as
  `verify-agent-base.sh`). **Deliberately NOT built:** per-element y/N (confirmation fatigue; worktree
  `-d`/uncommitted-warn + branch `-d` already guard those — plan-delete is the sole irreversible step
  and keeps its single y/N) and auto-`/cleanup`. Files: `hooks/scripts/cleanup-cleanable-notice.sh`
  (+`.test.sh`, wired SessionStart #4) · `scripts/plan-landed.sh` (`--quick`, `STEPS=`) · `skills/cleanup`.
  **Hardened 2026-06-18:** (A) the predicate now **derives `$DEFAULT`** (`origin/HEAD →
  init.defaultBranch → main`) exactly like `locate-ladder.sh` instead of hardcoding `origin/main` —
  portable to `trunk`/`master` repos and consistent with the harness's own derive-don't-hardcode rule
  (closed a self-introduced inconsistency); (B) the notice also emits a **`⚠ no durable anchor`** line
  for any plan with neither `pr:` nor `plan_id:` — that plan can NEVER be cleaned (a forgotten
  `plan_id`/trailer = a config defect, not WIP), so the silent failure the durable key was meant to
  prevent is surfaced loudly. In-progress KEEPs (unshipped / no-trailer-yet) are NOT warned.

## Adding new hooks

1. Place under `~/.claude/hooks/scripts/<name>.sh`.
2. Register in `~/.claude/settings.json` under the appropriate event/matcher.
3. Write `<name>.test.sh` next to it (same dir).
4. Ensure `bash run-all-tests.sh` still exits 0.
5. Add a CHANGELOG.md entry with date, file, why, test-suite delta.

## When in doubt

Run `bash ~/.claude/hooks/scripts/run-all-tests.sh` — if green, the harness
itself is healthy and the bug is probably in your project's code, not here.
